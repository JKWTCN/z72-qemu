# 附加控制器的独立启动环境

控制器 C 1.30.00 固件的初始栈为 `0x20000C08`，复位入口为
`0x080002B5`。原厂复位流程完成早期时钟配置，再将前 `0x1C4` 字节
向量表从 `0x08000000` 复制到 `0x20000000` 并更新向量基址。
运行时使用的内存上界为 `0x20040000`。

`nikon-z72-controller-lab` 是用于继续分析固件的独立机器。它使用
Cortex-M4 执行环境、256 KiB SRAM、1 MiB 只读固件窗口及零地址
复位别名。CPU 时钟 100 MHz、参考时钟 12.5 MHz、96 条外部中断
和四位优先级均为实验配置，尚不能确认实际芯片型号与完整参数。
固件通过 `-kernel` 加载，由自身向量决定复位栈和入口。

实验机器的 `power-switch` 属性提供 G 组引脚 5 的外部电平，默认
为 `on`；可通过 `-M nikon-z72-controller-lab,power-switch=off` 选择
低电平。运行期间修改该属性只驱动输入线路，不改写固件状态。
复位保留外部电平，输出模式仍使用自身锁存值。迁移包含开关状态，
但迁移往返尚未验证。该输入身份来自电源管理路径的推断，不能
据此确认实际接线。原厂辅助函数 `0x08038C04` 使用的描述符
`0x2001F1B8` 指向端口 `0x40021800`、掩码 `0x20`；高电平使其
返回零。探针验证两种电平都到达原厂配置的输入引脚，尚未验证
它们引起完整电源状态转换或串行初始化。
另一个实验属性 `wake-input` 驱动 G7，默认低电平，其实际信号身份
尚未确认。两种属性都只驱动物理输入，不设置原厂任务或消息状态。

时钟配置窗口位于 `0x40023800`，原厂代码等待偏移 `0x00` 的
振荡器及 PLL 状态，并读取偏移 `0x08` 的时钟源状态。模型同步
反映使能与源选择；`clock-completion=off` 用于验证原厂等待仍然存在。
电源配置 `0x40007000` 和闪存控制 `0x40023C00` 当前仅提供配置存储。
这两个窗口尚无电源、闪存操作及独立复位语义。

运行时自然进入原厂软件中断 94（异常编号 110），处理入口为
`0x08020120`。随后配置 `0x40000C00` 的定时器，写入预分频值 4、
重装值 `0xFFFFFFFF` 并启动计数。独立机器使用已有定时器组件，
以固定 100 MHz 输入时钟连接到中断 50；这不证明其他计数模式或
实际硬件定时精度。

原厂随后进入引脚辅助函数 `0x08043ADE`，首次访问为向
`0x40020818` 写入高半字复位掩码。独立机器现提供八组引脚窗口，
从 `0x40020000` 起每组间隔 `0x400`。方向、类型、速度、偏置和
复用配置支持原厂的字访问；输出锁存限制为 16 位，偏移 `0x18`
对高半字执行清零、低半字执行置位。输入读回反映输出方向下的锁存
值，以及未连接输入的上拉／下拉偏置。未偏置输入默认低电平。
开漏电气行为、复用外设驱动、引脚锁定、外部中断与实际复位默认值
尚未覆盖。模型拒绝输入寄存器写入、非字访问及未支持的偏移。

原厂引脚初始化自然到达 `0x08048A28` 返回指令，八组输出锁存值
分别为 `0, 0, 0x800, 0x8A20, 0, 0x2090, 0x200, 0`，无异常。
后续时钟访问准备向 `0x40002824` 写入 `0xCA`、`0x53` 解锁值，
并使能电源配置中的备份访问位。该准备函数自然返回至 `0x080398EE`，
控制器上下文保存的时钟基址为 `0x40002800`，无异常。继续执行的
当前模型使 `0x40005400` 的原厂总线配置正常返回至 `0x08043F92`，
返回值为零，驱动状态为 `0x20`。后续原厂引脚清理正常返回至
`0x080438D0`，相应引脚恢复输入模式。随后 DMA 初始化正常返回，
流基址为 `0x40026040`，详见 [DMA 配置与传输](controller_dma.md)。
后续比较计时器配置与中断已通过原厂执行验证，见下文。控制器侧完整串行通信、外设 DMA 请求
和控制器到主处理器的线路仍需实现与验证。
已恢复的帧分片与串行初始化路径见[控制器传输](controller_transport.md)。

独立时钟模型提供写保护序列、20 个备份字、日历配置存储和同步
初始化状态。偏移 `0x0C` 的初始化请求位 7 控制就绪位 6；退出后
置同步位 5。控制寄存器中的告警／唤醒使能位反向决定相应配置就绪位。
`completion=off` 保留请求而不发布初始化或同步完成。低频时钟使能
在配置窗口的 `0x70`、`0x74` 同步反映就绪。这些都是局部实验合同。
模型没有日历时间推进、告警／唤醒中断、备份电源保持和完整访问时序。
实验机器复位会清空日历与备份字，与实际备份域的保持行为尚未对应。
原厂完整日历初始化尚未验证；当前原厂探针只验证访问准备返回。

两条总线位于 `0x40005400`、`0x40005800`，默认未连接目标。模型支持
字配置、软件复位、START 地址阶段、未连接目标的 NACK 和 STOP。
状态偏移 `0x14` 的位 0 表示 START 完成，位 10 表示应答失败，
失败位写零清除；偏移 `0x18` 在总线持有期间为 3，STOP 后为零。
`start-completion=off` 保留请求而不进入可发送地址状态。显式连接目标时，
支持七位地址、字节发送、重复 START 和有界接收尾部，详见
[总线目标与原厂传输](controller_i2c.md)。DMA 尚未覆盖。
两条总线的事件／错误中断分别接到 `31/32`、`33/34`。控制偏移
`0x04` 的位 9 使能事件、位 8 使能错误。原厂启动的未连接请求
已自然触发异常 47、48，原厂重定位后的公共入口为 `0x080201FD`，
随后完成引脚清理。配置和错误处理成功不等于目标数据传输成功。

线路选择窗口 `0x40013800` 提供有界字配置，四个引脚路由字从偏移
`0x08` 起。外部中断配置窗口 `0x40013C00` 提供六个字，软件请求
偏移 `0x10` 置本地 pending，偏移 `0x14` 写一清除请求和 pending。
两个配置窗口均随实验机器复位清零。GPIO 的 pad 输出提供输入读回
对应的电平，线路选择的四个字为十六个引脚各选择一个端口。
偏移 `0x08/0x0C` 使能上升／下降沿；匹配的电平变化置 pending，
即使中断屏蔽也保留状态。偏移 `0x00` 与 pending 共同决定中断
线路；解除屏蔽会投递已保留的请求。软件请求按位累积，写一清除
pending 同时清除对应软件请求。前五个引脚分别连接中断 6..10，
引脚 5..9 共享 23，引脚 10..15 共享 40。清除一个来源不会撤销
同组其他来源。当前仅支持低十六位的 GPIO 中断投递，尚无仅事件
唤醒、内存重映射及完整电气模型。配置设备迁移版本为 3，包含各
端口电平与首次采样状态；迁移往返尚未验证。

原厂配置为 G7 选择端口 6，并使能两种边沿。实验输入依次置高、
置低时，原厂均自然进入公共入口 `0x080201FC`，异常号为 39，
对应中断 23；返回点 `0x08020238` 已清除 pending 位 7，无异常。
这是边沿投递与原厂应答的证据，不能证明完整电源唤醒或串行服务
已经初始化。

电池接点输入和常规模拟量采样的原厂路径见
[模拟量采样](controller_adc.md)。当前电源任务反复得到未就绪结果，
默认未连接场景中，初始化任务仍等待其电源就绪事件，串行服务的后续初始化尚未执行。
显式装载实验配置并连接实验目标后，原厂电池准备检查已通过；
这仍不能证明电源就绪事件，见[配置数据和供电选择](controller_flash.md)。
显式连接地址 `0x4F` 的实验目标后，原厂映像在默认输入下已发出
电源就绪事件，并完成两路串行驱动配置；见[后续启动证据](controller_start.md)。

`tools/controller_core_probe.py` 检查原厂复位、时钟返回、向量复制、
软件中断、定时器配置、引脚初始化、日历访问准备、总线配置及引脚清理返回；禁用时钟完成的反向场景
要求向量尚未复制且无异常。探针只读取寄存器与内存并设置执行断点，
不写入固件运行状态。结果见
[控制器启动证据](../../artifacts/controller_core_validation/report.json)。
该探针使用独立环境。控制器也可装入双引擎机器的私有地址空间，见
[组合运行](controller_embedded.md)；完整启动、控制器通信和菜单显示仍未验证。

原厂比较计时器配置在 `0x08039394` 返回零，驱动状态为 1，
基址为 `0x40014800`，预分频为 49，上限为 `0xFFFF`，计数和
比较中断已使能。随后原厂公共辅助函数 `0x08041318` 自然执行，
异常号为 42，对应外部中断 26，比较标志和使能位均已置位，
无硬件异常。当前合同及限制见[比较计时器](controller_timer.md)。

`tests/test_controller_gpio.py` 通过合成 Thumb 指令检查八组引脚的
锁存、置位与清零、偏置、配置复位和不支持访问的精确异常。
`tests/test_controller_rtc.py` 使用同一合成执行环境，检查写保护、
解锁、初始化与同步状态、备份字隔离、复位、精确访问异常及禁用完成。
`tests/test_controller_i2c.py` 检查两个未连接总线的地址阶段、NACK、
STOP、软件复位、非法访问及禁用 START 完成。
`tests/test_controller_routing.py` 检查路由字隔离、软件 pending、
定向应答、十六条边沿与八组端口、屏蔽期间保留状态、共享中断、
外部开关、配置复位及不支持访问的精确异常。
