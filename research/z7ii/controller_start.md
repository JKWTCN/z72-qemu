# 原厂电源就绪和串行初始化

`tools/controller_start_probe.py` 使用完整原厂控制器 C 1.30.00 映像
和实验机器默认输入，不补入配置数据，不覆盖模拟量通道，也不修改
固件运行内存。唯一增加的设备是在 `controller-i2c0` 上、七位地址
`0x4F` 的实验寄存器存储。它允许原厂程序写入并读回电源配置，
不代表实际电源器件的电气响应或状态机。

分析固件可确认，电池回调中的分类结果并非完整上电结果。原厂
电源事件 `0x10` 处理函数 `0x08037554` 执行定时器准备、电源目标
配置、线路操作和后续时序。配置失败才转入关闭处理。此前仅观察
电池回调、配置回退或关闭循环，不足以确定所有上电阻点。

连接实验目标后，原厂流程自然到达：

- `0x08021418`：回调事件参数为 `0x04060002`，对应电源就绪。
- `0x0802137C`：初始化任务的原厂等待返回，输出标志包含位 0。
- `0x080343A4`：等待之后的原厂串行发送初始化入口。
- `0x08034574`：第一路串行配置返回，驱动状态为 1。
- `0x08034846`：第二路串行初始化返回，驱动状态为 1。
- `0x080309A8`：通信计时器配置返回，驱动状态为 1。
- `0x0803AD58`：附加串行窗口配置返回，驱动状态为 1。
- `0x0803CDF4`：共享更新计时器配置返回，驱动状态为 1。
- `0x08035708`：输入捕获寄存器配置完成，驱动状态为 1。
- `0x080213C2`：电源就绪后的两轮设备初始化均已执行。
- `0x08041710`：通信比较与断路公共处理函数自然执行，异常号 59。
- `0x0802D62E`：第四路串行窗口以主机模式完成配置。

这些节点均通过执行断点和只读检查验证，无硬件异常。未连接目标
场景则到达原厂关闭处理 `0x08038380`；探针同时设置就绪回调断点，
防止把意外发布就绪的运行误判为失败路径。结果见
[原厂后续启动证据](../../artifacts/controller_start_validation/report.json)。

E9 对应原厂资源 73，描述符端口为 `0x40021000`、掩码 `0x200`。
`auxiliary-input` 属性显式驱动该输入，默认低，机器复位保留电平。
原厂辅助检测稳定高电平返回 0，稳定低电平在十次间隔检查后返回 1，
从而进入不同的供电处理。实际电气身份仍需确认。机器输入迁移版本
为 5，旧版本恢复时此输入置低；迁移往返尚未验证。

带配置和外部输入的实验场景也验证了上述就绪与等待返回，但不是
最小必要条件，见[配置与供电选择](controller_flash.md)。配置区域为空
会改变电池处理分支，不能据此断言电源就绪必然被阻止。

当前探针检查附加串行和计时器配置、电源后的两轮设备初始化、
共享计时器中断，并在两秒观察窗口内检查系统节拍继续推进。
连接场景的本次节拍从 675 推进至 1858，最终硬件异常状态为零。
探针检查实际基址、
控制字、状态字及 DMA 通道，见[串行模型](controller_spi.md)和
[计时器模型](controller_timer.md)。此观察窗口没有新的缺失访问异常，
但不能证明所有后续条件均已满足或长期运行无故障。
原厂实际传输、控制器到双引擎的线路和菜单显示仍需实现与验证。
