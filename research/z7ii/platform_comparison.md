# Z7 II v1.70 与 Z30 v1.20：固件结构和双处理器分析

以下偏移均为各自拆分 BIN 内的文件偏移，不是运行时地址。

## 结论

Z7 II 使用独立的 master/slave EXPEED 固件；两份均具备 ARM 多核启动、SMP T-Kernel 和对应的主从通信实现。Z30 的单份 eg2090 同样包含 SMP 启动，因此必须区分 EXPEED 内部 CPU 多核与两颗 EXPEED 之间的协作。

slave 的任务配置集中在静照/实时取景后端、图像加速器调度及文件/数据服务。master 保留完整 AF/CV、UI 与管理任务族。这与实际通信代码共同支持“第二颗 EXPEED 分担图像后端和数据服务”的判断，但还不能确定每种模式下的逐帧、逐阶段分配，不能断言按奇偶帧或左右半幅分工，也不能称 slave 是专用 AF 处理器。

PNG 仅统计签名，不是逐张图片完整性验证。EX 等长不代表内容相同。独立 VR 镜像是否包含只是包结构事实。本次未对 EX/TPJ/VR 做完整函数级差异分析。

三份 eg 都包含同族服务及硬件设备名称，软件平台有明显延续性。Z30 也包含 DualEngineService / BDualEngineProtocol 名称；不能仅凭 Dual/Slave 字样断言相关功能启用。Z7 II 的实质区别是独立 slave 镜像、DUALEG 任务与主从传输实现。

## EXPEED 内部 CPU 多核

| 证据                  | Z30 eg2090 | Z7 II master | Z7 II slave |
| --------------------- | ---------- | ------------ | ----------- |
| 起始 ARM B 的目标     | 0xBC88     | 0xBC88       | 0xBCD4      |
| MPIDR 读取位置        | 0xBD2C     | 0xBD2C       | 0xBD78      |
| SMP 内核横幅          | 0x32F45    | 0x101455     | 0x32E4D     |
| Core1 idle 统计字符串 | 0x3A5C8    | 0x1E79D8     | 0x367E4     |

启动指令实际读取 `mrc p15,0,r0,c0,c0,5`，随后 `and r0,r0,#0xf`，并在多个 CPU 模式下执行 `sub r1,sp,r0,lsl #14` 分配独立栈。master 和 Z30 对应段相同，slave 对应地址后移 0x4C。

这确认多核初始化支持，不能据此统计实际启用的全部 CPU 核数，或判断某个任务固定绑定 CPU0/CPU1。任务记录首字段常为 0/1/2，但未追到消费者，暂不直接称为 CPU affinity。线程数量不等于硬件核数。

## 两颗 EXPEED 的通信实现

| 功能                  | master    | slave    |
| --------------------- | --------- | -------- |
| 初始化两个同步对象    | 0x367DE0  | 0x40C98  |
| 初始化通信区头部      | 0x367E08  | 0x40CC0  |
| DUALSEND 字符串       | 0x3681D0  | 0x41088  |
| DUALREMP 字符串       | 0x3681E0  | 0x41098  |
| 环形消息接收/回调分发 | 0x367F84  | 0x40E3C  |
| 地址映射/边界检查     | 0x3680E4  | 0x40F9C  |
| DUALEG 任务配置       | 0x2427488 | 0x852AB0 |

已通过原始字节反汇编核对的行为：

- master 初始化入口 0x1E1444 / 0x1E1458 分别调用上述初始化函数，slave 对应 0x349B4 / 0x349C8，存在真实调用。
- 初始化写入 `0x00C00108` 和 `0xAA550001`。master 本地通信区常量为 `0xB7CF0000`，slave 为 `0xC60F0000`；尚未命名具体物理总线。
- slave 0x40E3C 接收路径检查魔数，按 192 个槽位循环，每槽 264 B（8 B 头部 + 最多 256 B 有效载荷），检查类别/长度，按回调表 BLX 分发，更新索引前执行 DMB。
- slave 0x411DE 发送路径检查魔数、类别/长度，处理满队列，填写序号、类别、长度及内容，执行 DMB 并发布索引。
- slave 0x40F9C 遍历 24 B 映射记录，验证请求地址和长度在源范围内，再以目的基址加偏移转换地址；互斥保护，失败返回 -1。
- slave 0x40DDA 的一条复制路径要求 8 B 对齐，通过 0x147840 / 0x14784C 的 ARM LDRD / STRD helper 读写，属于 CPU 复制，不能称为 DMA 传输。
- slave 0x108EA0 函数有成组的远端地址映射与复制调用，例如 0x108EC4、0x108ED0、0x108F0E、0x108F1A、0x108F50、0x108F5A；相关结构类型尚未完整恢复。

消息队列与图像缓冲是不同层次。256 B 的消息上限不代表图片只能传 256 B；较大结构/图像可通过映射地址和其他数据路径承载。整帧传输路线还需继续确认。

## 任务配置反映的分工

按相同结构提取连续记录：12 B 名称 + 4 个 LE 整数，每条 28 B。只接受字段合理且有相邻记录的条目，未把孤立字符串计作任务。

- master：0x2425508–0x2427568，共 293 条。
- slave：0x852084–0x852B04，共 97 条。
- Z30：0x204AC88–0x204CBB4，共 282 条。

| 功能族       | master                                                          | slave                    | 解释                                               |
| ------------ | --------------------------------------------------------------- | ------------------------ | -------------------------------------------------- |
| UI / 管理    | APPMENU、APPPLAY、APPLV、GUISRV 等                              | 该任务表未找到对应任务族 | 完整交互和管理主要保留在 master                    |
| AF / CV      | AFSVC、AFLENS、AF_AREA、CVSRV、32 个 CVST 工作任务、IPUS/IPUDRV | 该任务表未找到对应任务族 | 不支持 slave 专用于 AF/眼部识别的断言              |
| 静照后端     | STGBAYER、STGSFLT、STGIMP、STGRS_A、STGEN_A、STGRAW 等          | 同族记录存在             | slave 配置包含静照处理能力                         |
| 实时取景后端 | LVIIP、LVMIPU、LVSFLT、LVENC 等                                 | 同族记录存在             | slave 配置也包含 LV 处理能力                       |
| 图像硬件调度 | IMPIIP0/W1–W9、IMPMIPU0/1、IMPJPGEN、IMPRAW 等                 | 同族记录存在             | 两份都配置图像加速器调度任务                       |
| PC 后端      | BE_RECPC、STGTAGPC、STGRECPC、IFMTPC                            | 同族记录存在             | PC 后端也出现在 slave；不证明每张图两颗并行应用 PC |
| 文件/卡服务  | FILESRV、CARDPS0/1、FILECOM、FILEWM 等                          | 同族记录存在             | 数据/文件服务参与协作；不证明某卡槽固定归 slave    |
| 双引擎协调   | DUALEG、BE_COM、BE_COMLV 等                                     | 同族记录存在             | 与实际主从通信代码互相印证                         |

slave 的 97 条记录名称全部在 master 表中出现，但配置字段未必相同。STGIMP：master `[2,22,4096,0]`，slave `[1,22,4096,0]`；DUALEG：master `[2,7,4096,0]`，slave `[1,4,5012,0]`。共享命名和基础框架，按角色配置不同；运行时创建和启停条件仍待追踪。

相比 Z30，master 表新增 BE_COM、BE_COMLV、IFMTCOM、IFMTPC、IMGBCOM、CARDCOM、FILECOM、FILEWM、FILEWP 等任务，支持后端/通信分工推断。PKGB1/PKGB2/PKGBCOPY 在 Z30 也存在，不能把它们单独视为双 EXPEED 独有证据。

slave 通用服务名表仍列出 FaceDetectService 和 PictureControlService 等名称。服务名称存在与完整 AF/CV 工作任务配置存在，应分别判断。

## 证据边界与后续研究

ARM 与 Thumb 指令混合，代码区、数据区和运行时映射必须分别判断。缺少直接指针引用不代表内容未使用；宽范围调用特征可能在数据中偶然出现，只将有局部指令及访问上下文支持的位置作为主要证据。

需要继续恢复消息回调表、BE_COM/BE_COMLV 与任务创建及启停条件，确认较大图像缓冲的传输路径。不能将 Z30 的局部运行时映射直接推广到 Z7 II 全镜像。
