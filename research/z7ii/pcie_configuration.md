# PCIe 初始化配置窗口

从引擎完成共享元数据复制后，原厂 PCIe 初始化在 `0x1008a3b4`
读取 `0x2b20003c` 时发生访问异常。基础窗口的前十二个配置字已存在，
缺少的是后续配置、链路查询和根配置空间访问。

配置读取函数 `0x1008a3b0` 和写入函数 `0x1008a326` 访问偏移
`0x3c`、`0x4c`、`0x50`、`0x54`，将配置字拆成软件位域再写回。
初始化函数 `0x1008b0e8` 还对偏移 `0x300` 的位 0 做读改写。
这些地址现补为独立配置字，整机复位清零。

根配置地址由 `0x1008ad34` 计算。本次使用的根配置空间为
`0x2a900000`，初始化依次访问 `0x8bc`、PCI 配置字段和地址转换窗口。
模型仅支持分析固件确认的配置偏移；其他偏移、非对齐访问和字节访问
继续失败，没有把整页映射成任意寄存器存储。

| 根配置偏移 | 当前行为 |
| --- | --- |
| `0x004`、`0x010..0x01c` | 已使用的命令和地址配置字读回 |
| `0x050`、`0x078..0x090`、`0x098`、`0x0a0`、`0x168` | 已使用的配置字读回 |
| `0x80c`、`0x8a8`、`0x8bc` | 初始化配置字读回 |
| `0x900` | 方向位 31、区域索引低四位；其他选择位清零 |
| `0x904..0x91c` | 每个方向、区域独立的七个描述字 |

区域描述只保存配置，没有接通地址转发、端点、数据传输或 MSI。
主从角色使用各自的根配置状态。复位清零所有描述字和当前选择。
状态格式升为 27，拒绝旧实验版本，避免将长度不同的配置数组读错；
本阶段没有验证迁移操作。

链路读取函数 `0x1008a422` 使用控制窗口 `0x58`、`0x5c`。
当前没有连接端点，这两个只读状态保持零，软件写入不能制造链路状态。
原厂 `0x1008b32e` 最多循环 500 次，每次睡眠 1 个单位，检查
`0x58` 位 16..21 是否为 `0x11`；模型没有强行令该条件成立。

修改后的有界原厂运行越过先前的访问异常，从引擎在 `0x100677da`
提交资源 8、操作 2、长度 48 的回复。回复槽位为 1，结果字为
`0xfffffccb`，即 -821。该结果不是成功。后续已观察到主引擎接收回复，
卡查询等待结束；接收字段和当前供电提示路径见
[前台等待分析](message_wait.md#查询回复与供电提示)。
后续前台仍为 `APPMSG`，模式为 8，没有观察到菜单启动。
原厂运行仍使用此前的实验驻留数据、采样参数和显式 GPIO 输入，
不能据此证明正常启动完成。

板级检查覆盖两种角色的配置读回、只读状态、四个不同方向和索引的
区域隔离、最高索引、选择位屏蔽、配置不制造数据传输、非法访问及复位清除。
编译和这些检查通过，记录见
[PCIe 配置验证](../../artifacts/pcie_configuration_validation/report.json)。
