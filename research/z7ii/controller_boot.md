# 控制器链与门控序列

引脚组配置返回后,库初始化链(master `0x1E003A` / slave `0x32F7A`)调用控制器
序列:master `0x1E0DAC` / slave `0x337A4`。以下代码位置均为 C 1.70 EG 文件偏移,
运行时加 `0x10020000`。

## 控制器字与延时

函数先把六个常量写入 `0x04281000+0x138..0x14C`,再对 `+0x28` 做两组位清理
(AND `0xFFFCFFFD`,BIC 4)。随后在计数器 `0x04266000+8` 上等待原始差值
`0x12C0`(48 MHz 下约 100 微秒)——该等待无软件超时。延时后对 `+0x28` 再
BIC 8,并把七个设置字写入 `+0x00..+0x14` 与 `+0x24`:

| 偏移 | 值 |
| --- | --- |
| `+0x00` | `0x00508880` |
| `+0x04` | `0x80808888` |
| `+0x08` | `0x80300000` |
| `+0x0C` | `0x00008008` |
| `+0x10` | `0xB0100010` |
| `+0x14` | `0x00980009` |
| `+0x24` | `1` |

同时向 `0x04280000+0x78..0x88` 写入五个派生字:`~0x8C000000`、
`0xB0100010` 算术右移 31 位(`0xFFFFFFFF`)、`0x01FFC1FF`、`~0xCE000000`
和 `0x4EE`。

## 门控序列

函数尾部的门控子程序(master `0x1E0E56` / slave `0x3385A`)每次把
`r0 << 12` 写入 `0x04287000`、把 `0xA1` 写入 `+0x10`,然后轮询 `+0x04`
的位 0,就绪后向 `+0x04` 写 1 应答并返回。

单步执行确认了实际调用序列:master 先以 r0=0、r0=1 调用两次,`0x1E0E4C`
的恢复指令不改写 PC,流程落入 `0x1E0E50` 的尾桩,以 r0=3 第三次进入门控
子程序,最后经 `bx lr` 返回 `0x1E003E`。slave 在正文中以 r0=0..3 调用四次,
尾桩为 r0=4。因此最终 `0x04287000` 值为 master `0x3000`、slave `0x4000`。
仅凭线性反汇编会把 master 误判为两次调用;本阶段以实际单步路径为准。

## 有限模型

`nikon-z72-boot-config` 新增 22 个字:`0x04281000` 块 14 个、`0x04280000`
扩展 5 个、门控 3 个。除 `0x04287004` 外均为纯存储。`0x04287004` 的读回
恒置位 0(同步就绪假设,与既有完成/发送就绪模型一致),写入照常保存,因此
原厂轮询立即通过、应答写 1 落地。设备状态格式升为版本 8。

`controller-config=off` 时不注册这一块,保留 `0x04281138` 的未映射异常
(`DFSR 0x808`)作为负对照。门控真实硬件语义(各 r0 相位的含义、时钟或
复位效果)与总线行为均未实现。

## 原厂执行与下一边界

2026-10-10,两个角色各通过原厂和关闭场景。双核从原厂复位连续执行:进入
`0x1E0DAC`/`0x337A4` 后核对延时前后计数器差值不小于 `0x12C0`,返回调用方
后核对全部 22 个字、r4-r8/lr 与栈恢复。master 门控终值 `0x3000`、slave
`0x4000` 与单步路径一致。

返回后的下一个调用 master `0x1E7310` / slave `0x33B18` 把 1 写入
`0x20010044`,随后按指针表复制 19 个字并继续展开配置。该首次写入触发
数据异常:

| 角色 | 写指令 | DFSR / DFAR |
| --- | --- | --- |
| master | `0x1E7318` | `0x808` / `0x20010044` |
| slave | `0x33B20` | `0x808` / `0x20010044` |

`0x20010000` 控制器块的契约尚未接入。RTOS 完整调度、原厂 IRQ 处理与菜单
仍未验证。

## 验证与复现

```sh
python tools/controller_boot_probe.py --master /path/to/eg1840_mas_01700.bin --slave /path/to/eg1840_sla_01700.bin --qemu .build/build/qemu-system-arm --destination .local/controller-run
```

四个场景:两角色原厂路径(计数器延时、22 字读回、门控终值、调用方恢复、
下一边界状态)与两角色 `controller-config=off` 负对照(在 `0x04281138`
首写处中止)。同时重跑引脚组与字符接口探针(各自显式关闭本块以保留记录
边界)、`tests/test_board.py` 与 `analyze/` Python 检查,全部通过。完整
证据的精简版本与源码、报告哈希见
[验证报告](../../artifacts/controller_boot_validation/report.json)。
