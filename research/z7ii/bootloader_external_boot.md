# Bootloader 与外部启动(BOOTDISK 类比)研究

2026-10-26。分析对象为本地 Z7 II C 1.70 五个容器成员、十二个历史
更新包(C 1.01–C 1.70)、以及两份包外文件(`nkld01_decoded.bin`、
`bvr_flash.bin`)。全部结论来自静态字节解码、指令窗口核对与既有
研究文档的交叉引用;没有连接相机,没有写入任何存储。证据与复现
入口见[引导链调查元数据](../../artifacts/bootloader_survey/report.json)。

## 结论

1. **更新包内不存在引导加载程序成员。** 十二个历史版本的容器目录
   均只有 EX、TPJ、master、VR、slave 五类成员,没有引导区成员
   (与[历史更新包检查](update_history.md)的独立复核一致)。
2. **机身 NOR 的引导区唯一且无备份。** 从 master 启动复制数据完整
   解码的 33 项区域表显示,`0x10000000–0x1001FFFF`(0x20000 字节)
   是仅有的引导区,两份描述符(区域 0/1)指向同一地址,没有备用
   bank;主引擎固件区(区域 2,`0x10020000` 起 43 MB)同样没有
   备用地址。只有 `0x12A80000–0x12E60000` 的数据链(区域 11–16)
   带备用地址。主固件损坏时不存在片上回退,更没有"失败后从卡
   恢复"的隐含机制。
3. **主引擎永远从机身 NOR 就地执行。** master 首条 ARM 分支位于
   运行地址 `0x10020000`,目标 `0x1002BC88`;异常向量
   `0x10100010`。卡栈在 RTOS 与文件系统服务完成初始化之后才可用
   (见[固件更新路径](firmware_update.md)的存储卡栈分层);启动
   前段不存在任何卡访问。
4. **不存在魔灯式 BOOTDISK 标志。** 五个成员与两份包外文件中,
   `BOOTDISK`、`bootdisk`、`AUTOEXEC`、`autoexec`、`LOADER`、
   `loader` 全部为零命中;`boot/Boot/BOOT` 的全部命中都属于电源
   编排命令名、快速启动任务、Wi-Fi/BOOTP 协议文本或重启横幅,
   详见下文逐条定性。没有任何配置索引、常量或文件名约定构成
   "从外部介质启动"的开关。
5. **外部介质上的代码要进入机身,唯一已识别的入口是固件更新流程,
   且受认证约束。** 整包路径执行 `SHA1(解码主体 || K8)` 检查,
   `K8 = B8 XOR S8`,B8 取自引导窗口 `0x10000088`(见
   [整包摘要说明](firmware_update.md#整包摘要与-k8-的区别));
   Z30/Z6 上公开可行的裸 EG 成员安装路线,在 Z7 II 的目录例程中
   被拒绝([双机型对照](z6ii_update_comparison.md)、
   [公开资料对照](public_update_evidence.md))。
6. **`NKLD????.BIN` 不是引导程序更新,而是镜头数据容器。** 它是
   卡上更新文件体系中类别 7 的模板;本地 `nkld01_decoded.bin` 的
   头部符合公开工具链已知的镜头数据格式(魔数 `0x87C7CAAC`,
   版本 1.04,199 个按镜头 ID 的条目),与引导区(131,072 字节,
   无该魔数约定)没有结构对应关系。
7. **类别 7 在相机自身流程中不可执行。** 菜单扫描对类别 7 只关闭
   文件并返回码 3(与"裸 EG 被拒"同一路径);独立成员路径对
   类别 7 不做内容校验直接接受记录;菜单执行门控只放行类别
   2/4/8。三层组合后,包内固件没有任何面向卡面或用户的引导
   程序更新路径。
8. **第一级引导代码位于包外。** 引导区内容与更早的加载器(或
   掩模 ROM)未获得;上述阴性结论限定于分发包内固件。若取得
   引导区转储,应优先检查其中是否存在卡接口枚举、启动标志读取
   或失败回退路径——这是本问题剩余的唯一开放面。

## 机身 NOR 布局(区域表与对象表首次完整解码)

区域描述符(33 项,44 字节/项)与对象记录(81 项,28 字节/项)
位于 master 启动复制数据(`0xB185E5C4` / `0xB185EB70`),本次全部
解码。代表性行如下,完整表见[调查元数据](../../artifacts/bootloader_survey/report.json);
地址为每引擎各自的映射窗口。

| 区域 | 首选地址 | 备用地址 | 跨度 | 说明 |
| --- | --- | --- | --- | --- |
| 0/1 | `0x10000000` | 无 | `0x20000` | 引导区;B8 在 `+0x88`,CFI 几何在 `+0x4E` |
| 2 | `0x10020000` | 无 | `0x2940000` | 主引擎固件 XIP 区 |
| 3 | `0x12960000` | 无 | `0x60000` | 与 USB 调试捕获上传窗口吻合 |
| 9 | `0x12A40000` | 无 | `0x20000` | 计数区,更新服务以"读回-递增-擦写"维护 |
| 11–16 | `0x12A80000`… | `0x12E60000`… | 合计约 3.4 MB | 唯一带备用地址的双 bank 数据链 |
| 17/18 | `0x132C0000`/`0x132E0000` | 无 | `0x1FFFC`/`0x9FFFC` | 校准/调整数据的子对象分区 |
| 24–30 | `0x13540000`… | 无 | `0x180000`×7 | 标志为 RAM 型的 LUT/资源区 |

对象编号映射:对象 0→区域 0(引导区,可经通用写接口写入),对象
1/2 被通用写接口明确拒绝,对象 0x44→`0x133C0000`(启动路径实际
引用,非引导区),对象 0x49–0x4E→LUT 区。与
[引导材料存储](boot_material_storage.md)的结论一致并补全了全表:
引导区存在可写接口,但已识别的自然调用路径没有任何以引导区为目的
的请求;通用对象写入口的 14 条直接调用边选择的都是资源对象。

## 卡上更新文件体系:模板、记录与门控

master 内有 22 个 8.3 文件名模板与 `firmware\` 目录前缀,被两张
记录表引用:

- **扫描表**(成员偏移 `0x19603D0` 起,12 字节记录
  `[类别][模板指针][条件函数]`),其中 11 项进入菜单扫描循环
  (`0x37C360`):类别 1(EX)、2(EG)、3(VR)、4(整机包)、
  7(NKLD)无条件,其余带"设备在场"条件函数。
- **枚举表**(`0x1960590` 起,16 字节记录),增加镜头家族
  LF/ML/MA/TC/RG 与两类无线模板。

扫描的分派(成员偏移 `0x37C3DC` 的 TBB 表,本次按字节单位解码,
并与两类已知经验行为交叉核对:类别 4 接受原厂整包、类别 2 拒绝
裸 EG,均与[原生更新检查记录](firmware_update.md#原生目录访问与更新文件名选择)
一致):

| 类别 | 模板 | 扫描分派结果 |
| --- | --- | --- |
| 4 | `Z7_2_???.BIN` | 进入包目录检查 `0x37BC0E`(整包接受路径) |
| 2 | `EG1840??.BIN` | 头部校验 `0x37B0A2`(裸 EG 拒绝路径) |
| 5 | `_D_WT???.BIN` | 仅关闭文件,直接成功,无内容校验 |
| **7** | `NKLD????.BIN` | **仅关闭文件并置返回码 3(拒绝)** |
| 0、0xA | — | 同类别 7 的拒绝路径 |

独立成员路径 `0x37C47E` 的分派(偏移 `0x37C4F2` 的 TBB 表)对
类别 7 落到 `0x37C5DC`:存储记录指针后返回 0,不做任何内容校验,
也没有整包 SHA-1 调用。菜单服务段的执行门控要求条目数为 1 且
类别为 2、4 或 8(见[固件更新路径](firmware_update.md))。因此
NKLD 文件即便被枚举层接受为记录,也无法通过菜单服务执行;能驱动
独立路径的调用者不在包内已识别流程中。

十二个历史版本逐包核对:每版都有 NKLD 模板、扫描表与枚举表各
一条类别 7 记录,条件函数恒为空;`RG??????.BIN` 模板自 C 1.50
起加入。该机制跨版本稳定,不是某版本引入又移除的实验路径。

## NKLD 文件的定性

本地 `nkld01_decoded.bin`(119,436 字节)头部逐字段解析:

| 字段 | 值 |
| --- | --- |
| 数据偏移 / 数据长度 | `0x20` / `0xD9AA` |
| 总长(容器声明) | `0xD9CA`(55,754) |
| 版本 | 1.04 |
| 条目数 | 199 |
| 魔数 | `0x87C7CAAC`(公开工具链的镜头数据格式) |

公开参考实现按"16 字节条目头 `[长度][镜头 ID][子 ID][属性]`"
逐条目组织数据,条目按镜头型号区分——这是镜头数据文件,不是可
执行加载程序。文件长度超过容器声明,尾部还有约 63 KB 附加数据,
其分段来源无记录;这不妨碍定性,但说明该文件可能承载不止一个
分段。

载荷保持高熵,重复分组特征与[USB 日志通道](usb_debug_channel.md)
早前的观察一致。本次补充:该格式参考实现使用的两张变换表与
master 内整包摘要的两张表(运行地址 `0x12068276`、`0x12068376`)
逐字节相同,即镜头数据解密与整包摘要属于同一累加流密码家族;
但参考实现的 DSLR 常量(`0xB401C81B` + `NCDSLR`)以及 60 组
Z7 II 相关组合(含 `0x44B` + `Z_7_2` 等)均未解开本地文件载荷,
模型相关密钥材料仍未恢复。引导区为 131,072 字节且不含该魔数
约定;无论从尺寸、结构还是公开格式语义,NKLD 文件都不对应
引导区镜像。

## 外部启动证据的逐条定性(全部阴性)

对 master 的 `boot/Boot/BOOT/UPDATE/update/NKLD` 全部命中逐条核对:

| 命中 | 定性 |
| --- | --- |
| `NKLD????.BIN` ×1 | 卡上更新模板本身 |
| `<< SYSTEM RESTART/REBOOT >>`、`INIT-REBOOT`、`BOOTREQUEST` | 重启横幅与 DHCP/BOOTP 协议文本 |
| `eSyscController_BootShutDown(Notice)`、`eSyscCommandId_PowerOnBoot`、`InitializeFastBoot`、`StartTaskFastBoot`、`SyncExtBootUpFactorNotice`、`WakeUpFactorSyncHook` | 系统控制器命令名族,97 个命令名中全部"Boot"类均为电源开关与快速启动编排,无启动源选择语义 |
| `Booted ARM926 Firmware[Ver...]` | 外设模块固件横幅,位于无线驱动支持段 |
| `Fastboot Initialize and Start`、`boot-patch` | 驱动名与无线补丁格式 |
| `BootSTL.c` | RTOS 断言文件名 |
| 其余 `update` ×16 | PNG 读取器、更新服务日志串、无线驱动状态字 |

其余成员与包外文件:ex1840(系统控制器)、`_tpj01`、`vr1840`、
`bvr_flash` 对全部关键词零命中;slave 仅有 `SYSTEM REBOOT` 横幅、
`BootSTL.c` 断言文件名与 `Fastboot` 驱动名各一处。ex1840 作为
常开控制器既无启动决策逻辑也无卡/文件访问(电源与串行编排见
[控制器链](controller_boot.md)、[原厂电源就绪](controller_start.md))。

## 与魔灯 BOOTDISK 的机制对照

魔灯在 Canon 上的机制是:持久置位闪存/NVRAM 中的 BOOTDISK 标志,
原厂引导程序随后在每次开机时从卡读取 `autoexec.bin` 执行。Z7 II
的对应面逐项检查结果:

| 魔灯要素 | Z7 II 对应 |
| --- | --- |
| 引导程序可切换到卡 | 无标志、无配置、无文件名约定;卡在 RTOS 之后才可用 |
| 每次开机读取的卡上载荷 | 不存在;唯一卡载代码入径是菜单更新,一次性写回 NOR |
| 标志可由第三方持久置位 | 引导区写接口存在(对象 0)但无自然调用者;B8 未恢复 |
| 失败回退 | 引导区/固件区无 A/B;主固件损坏无片上回退 |
| 认证绕过 | 整包 SHA-1 + K8;裸成员路线被 Z7 II 目录例程拒绝(与 Z30/Z6 不同) |

## 边界

- 第一级引导代码(引导区 `0x20000` 内容或掩模 ROM)未获得;
  包内固件的阴性结论不能外推到该代码内部。
- B8 的初始化来源仍开放([引导材料存储](boot_material_storage.md)
  的未闭合项);取得引导区镜像后应先复现整包摘要,再检查其中
  是否有卡枚举或启动标志逻辑。
- `nkld01_decoded.bin` 与 `bvr_flash.bin` 的来源无记录;前者
  载荷未解,后者为 VR 页同族镜像,两者均不改变上述结论。
- 扫描分派与独立路径的行为为静态解码结论,并以两类已知经验
  行为交叉核对;没有在整机上放置 NKLD 文件做过实测。

## 复现

```text
python -B tools/bootloader_survey.py --master <C1.70-master> --nkld <nkld-file> --packages <history-directory> --tables <Firmware.cs> --members <ex> <tpj> <vr> <slave> <bvr> --report artifacts/bootloader_survey/report.json
python -B -m unittest checks.test_bootloader_survey -v
```

探针只做静态字节解码与身份校验,不导出固件,不修改原始输入,
不连接设备。历史包扫描需要本地更新包目录与解码表来源。
