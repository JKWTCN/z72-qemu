# 拍摄界面的错误显示与致命消息

分析固件并对整机运行做观察,把拍摄状态栏的 `Card`/`Err` 计数显示、
菜单退出后出现的 "Error. Turn camera off and then on again." 对话框
定位到具体绘制代码、字符串资源与状态字节。文件偏移为 master EG
成员内偏移,运行时地址为 `0x10020000 + 文件偏移`。

## 字符串资源银行与消息表

界面文本不使用内嵌指针,而是按 `银行/ID` 引用:控件字段保存
`{kind, id}`(文本设置器 `0x10739b1a` 将 kind 写入对象 `+0xc`、
id 写入 `+0x8`),渲染期再解析为文本指针。

UTF-16 消息银行(每语言一张表,全镜像共 36 张相同的 2532 项表):

- 表起点(英语,含错误消息):文件 `0x1079E4C`,每项 4 字节偏移。
- 字符串基址:`0x1109C5E0`(= 表结束处,表与文本相邻)。
- 字符串边界:第 k 项到第 k+1 项偏移之差;文本内 `\n` 分隔行。
- 验证锚点:ID `0x95` = `Initialization error.\nTurn camera off\n
  and then on again.`,ID `0x96` = `Error.\nTurn camera off and then on
  \nagain.`,与菜单画面显示一致。

固件内的 APPMSG 请求格式为 `0x2_XXXX`:高半字 2 选择 APPMSG
(`0x1062e474` 的分支 `0x1062e512`),低半字为消息参数
(历史观察 `0x200015` 与本格式一致)。

## 拍摄状态栏的 Card/Err 计数

计数绘制函数 `0x10529378`(文件 `0x509378`)每槽画三个文本
(控件 0xf/0x10/0x11,默认字符串 ID `0x306`);槽状态取自
getter `0x104aaba4` → 字节 `0xb1823a48+1`(当前组合实测为 0),
状态为 1/2/3 时按全局字节 `0xb181da91`(实测 0)选择 `0x2f8`
(字节=2)或 `1`。相邻函数 `0x1052928c` 在字节为 0 时追加绘制
ID `0x121b..0x121e` 的四个文本——即无卡/错误指示的字符串组。
`Err`/`Card`/`Full` 的 ASCII 字面量位于文件 `0x509350` 一带,
属另一银行(尚未恢复其 ID 表)。

整机采样:槽状态结构 `0xb1823a48` 全零(仅 `+0x28` 为 1),字节
`0xb181da91` 为 0,与上述绘制分支一致;菜单前后这些字节不变。

## 菜单退出后的致命对话框

整机复现:拍摄应用稳定后轻按菜单(前台→APPMENU)再按退出
(前台→APPLV),画面出现居中 "Error / Turn camera off and then on
again." 对话框,底部状态栏仍显示 Card/Err;此后菜单无法重开
(采集状态列表含 `0x3f`,为既有记录的边界)。

运行时排除与定位:

- 退出阶段状态追加入口 `0x1035ed5c` 断点全程未命中——对话框
  不经采集状态列表路径;`0x3f` 在菜单打开时追加,退出后不追加
  新状态。
- 显示树在退出后整体切换:APPLV 上下文 `+0x2ec` 起的四个对象
  数组指针从 `0xb1fa72f0/740c/7528` 换为 `0xb1fca32c/a448/a564`,
  对话框控件池位于 `0xb1fcxxxx`;控件 `0xb1fcb608` 在画面可见后
  字段 `+8` 为 `0x11b5`(属未恢复 ID 表的银行)。
- 对 `0xb1fcb610` 的写观察点只捕获显示服务模块
  (`0x10634720` 一带上下文 `0xb181b498`)反复调用的零填充循环
  (`0x10361044`,memset 家族):退出后界面进入持续重建循环,
  对话框控件被周期清零重建。
- 前台保持 APPLV(索引 3),未观察到 APPMSG 前台请求;对话框
  为拍摄应用内覆盖层。

## 尚未恢复

- 致命对话框的请求者(发送 0x96 号消息的调用链)与触发条件;
- ASCII 字符串银行的 ID 表(`Err`/`Card`/`Full`、`0x121b` 组、
  `0x2f8`/`0x306` 的解析);
- 退出后显示重建循环中固件等待的硬件契约(菜单关闭后采集管线
  重启失败的第一个等待点)。
