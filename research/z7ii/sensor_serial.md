# 图像接口串行程序与空资源输入

原厂 `102fe1ea` 按选择子取得资源程序，或即时构造少量命令，再调用
`1030621e` 发送长度表。当前实验资源头没有这些资源程序的内容：在
静音 F8 机身拍摄窗口中，六次资源长度表的首项为零。原厂发送函数对
空表直接返回成功，因此成功返回本身不能证明传感器配置已经执行。

[原厂片段契约](../../artifacts/sensor_serial/serial_contract.json)与
[原厂运行记录](../../artifacts/sensor_serial/validation.json)分别保留
隔离执行和实际机身拍摄的证据。本轮没有修改设备行为或生成新的曝光触发。

## 原厂发送规则

`tools/sensor_serial_contract.py` 校验 C1.70 主固件摘要，再执行下列原厂
函数；串行传输、GPIO 和完成结果使用显式合成边界。

| 函数 | 已验证行为 |
| --- | --- |
| `102fe126` | 输入类别 5 选择参数表第 3 列 |
| `102fe1ea` | 选择子 0..18 提交一个长度表；19、20 返回 1，不提交 |
| `1030621e` | 读取小端 16 位长度，以零结束；按长度推进载荷地址，首个包错误后返回 |
| `10367fe0` | 每个包分为至多 192 字节的块；字节零扩展为半字后交给 `10370a14` |

字节写入函数在整个包期间将选择 GPIO 拉低，结束时拉高，包括零字节及
错误情形。单块传输失败归并为返回值 2，但同一个包的后续块仍继续提交；
外层长度表遍历收到该错误后才停止。零长度表不会进入字节写入函数。

契约覆盖六个块传输情形（0、1、192、193、385 字节及跨块错误）、四个
长度表情形，以及全部 21 个选择子。另一个显式非空资源 fixture 检查原厂
选择器确实转交输入字节；其内容仅用于验证转交，不是恢复的传感器程序。

```sh
python tools/sensor_serial_contract.py --master <C1.70-master> --out .local/serial-contract.json
```

## 有界机身拍摄观察

只读函数入口观察共记录 25 次：8 次长度表入口、8 次字节写入入口、
3 次采样阶段处理入口、6 次采样命令分发入口。各观察点上限为 8 次，
不能据此列出整个拍摄过程的全部包或排除后续调用。

八次长度表入口中，资源选择子依次为 `7,8,9,2,5,7` 的六次调用均为空。
另外两次匹配选择子 3、4 的即时构造长度及载荷摘要。字节写入入口确实
命中，但这不等于完整线缆抓包，也未证明物理对端接受了这些命令。
运行全局 `b18a7808` 保存的串行通道为 8，对应寄存器基址 `2c0a0800`。
这些证据尚不足以解释命令地址、字节顺序、具体传感器或积分开始语义。

该窗口结束时机身状态为 `[2,0]`、驱动状态为 9，主 RAW 帧数为 1，四个
ARM 核采样的故障寄存器均为零。DSP 预处理仍明确跳过；本轮没有持久
写卡或回放复验。八个临时编码图像已清理，原有卡和用户要求保留的 JPG
保持不变，Git 仅保存代码、文字和摘要。

## 后续边界

当前 RAW 仍由配置触发生成，尚未恢复电子积分起点。
[光圈与 RAW 时序](iris_timing.md)中提前生成的现象不能用空程序的成功
返回解释为已完成曝光配置，也不能据此断言缺失程序必然包含全部曝光门控。

后续可继续寻找资源程序的实际来源，也可先恢复已观察消费者的计时字段，
为功能模型提供明确声明的实验参数。二者需要分别记录来源和适用范围，
并核对电子曝光、读出请求及镜头到位条件；不能把实验参数视为工厂数据，
或把通道使能写入直接视为积分开始。

后续的[可选计时输入](sensor_timing.md)声明了部分非零计时行，保留原厂
运算和加载路径；串行程序长度表仍为空，不能替代这些程序的内容恢复。
