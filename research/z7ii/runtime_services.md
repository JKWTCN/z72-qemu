# 初始运行时服务与堆区

本阶段分析 C 1.70 运行时的第一组核零服务初始化，补齐原厂堆边界对应的 RAM。
以下偏移均为 EG 文件偏移，运行地址为 `0x10020000 + offset`。

## 启动阻碍与修改

修改前，master 模型的状态 RAM 在 `0xB2C00000` 结束。原厂内存管理初始化在
`0xE8528` 写入该地址时触发数据异常；固件页表的相应项有效，缺少的是物理 RAM。
原厂配置对象给出的堆范围为 master `0xB2C00000..0xB5F00000`、slave
`0xC1940000..0xC5000000`，全部使用原地址段映射。

模型新增 master 51 MiB RAM 和 slave `0xC1A00000` 起的 54 MiB RAM；slave 堆的
前 6 MiB 已位于原有状态 RAM 中。原有窗口和实验清零设备的目的范围保持不变。
这些是软件范围对应的实验容量，不能作为实际 DRAM 芯片容量的结论。
适配 `virt` 的验证页表也增加互不重叠的 RAM 映射，保留原厂段属性；自然启动仍使用
原厂复制并安装的页表，没有替换指令或重新指定 PC。

## 第一组服务

| 步骤 | master | slave |
| --- | --- | --- |
| 服务组入口 | `0xE8F9C` | `0x1A970` |
| GIC 与核间回调配置 | `0xE6ECC` | `0x188A0` |
| 原厂返回零的钩子 | `0x100514` | `0x31EE8` |
| 原厂返回零的钩子 | `0x100440` | `0x31E14` |
| 内存池初始化 | `0xE8494` | `0x19E68` |
| 堆控制与空链表初始化 | `0xE8B54` | `0x1A528` |
| 返回 RTOS 调用者 | `0xE3C5C` | `0x1570C` |

五次原厂调用均返回零，恢复调用者栈。GIC 初始化设置分发器和 CPU 接口控制字为 1，
优先级屏蔽字为 `0xFF`，SGI 使能位为 `0xFFFF`，PPI 和 SPI 保持未使能，SPI
触发配置为零。原厂代码写入目标字 `0x01010101`；当前单 CPU GIC 的 SPI 目标
寄存器读回零，这是模型行为，不能推断真实主板读回值。
原厂核间回调配置使用 SGI 1 并将其优先级设为零，其余优先级读回 `0xFF`。
这里验证配置结果，尚未验证原厂 IRQ 处理程序实际接收或返回中断。

设堆起点为 `start`、终点为 `end`，原厂计算：

```text
pool_end = align_down_2048(start + ((end - start - 8) / 0x808) * 8 + 0x807)
count = (end - pool_end) / 2048
```

master 得到 `pool_end=0xB2C33000`、`count=26010`；slave 得到
`pool_end=0xC1977000`、`count=27922`。16 字节状态对象保存两个相同的计数、
堆起点和 `pool_end`。原厂代码写入起始头、首个空闲头和尾部头，更新边界对象；
另外设置大小字段 `0x800`，初始化属性为 `0`、`0x10`、`0x300`、`0x310` 的
四组自引用空链表。后续分配、释放和并发语义尚未验证。

## 下一设备边界

服务组返回后继续沿原厂路径进入共同回调 `0x12C`，从已初始化的数据指针取出
`0x04266000`，在 `0x134` 首次读取。该阶段首次验证时没有实现这个计时设备，读取
进入原厂数据异常向量；服务验证程序停在读前。后续
[计数模块阶段](runtime_counter.md)已接通这个设备，服务负对照通过关闭其接口
保留原厂访问异常检查。
回调随后涉及 `+0`、`+8`、`+0xC` 和 `+0x10`，但完整计数、使能与通用定时器的
关系需要下一阶段分析。没有用任意寄存器存储或伪造读数越过该边界。

## 验证

```sh
python tools/service_boot_probe.py --master /path/to/eg1840_mas_01700.bin --slave /path/to/eg1840_sla_01700.bin --qemu .build/build/qemu-system-arm --destination .local/service-run
```

七个场景覆盖两个角色的原厂路径、无效堆段负对照、未实现计时设备访问异常，以及
slave 选择位置位路径。成功路径检查 GIC 配置、全部五次返回、内存池状态、头尾、
保护字和四组空链表。负对照仅使 RAM 页表副本中的首个堆段无效，必须在原厂头部
写入时产生数据异常，然后恢复该项。原厂文件不变。

2026-10-10，七个场景、两种主板 RAM 检查、22 项 Python 检查、270 项渲染器 ASan/UBSan 检查通过；结构及显示回归通过。
证据见 [服务启动验证](../../artifacts/service_boot_validation/report.json)。
完整调度、LCD、菜单和两个处理器间通信仍未验证。
