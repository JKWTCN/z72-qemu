# 机身 VR 的有限通信模型

`nikon-z72-boot-config.virtual-body-vr=on` 在主引擎 SPI4 接入
`nikon-z72-body-vr`，同时启用外设 DMA。独立开关默认关闭；启用
`virtual-lens` 时也会接入本设备，避免镜头配置开启 DMA 后 SPI4 空悬。
这是通信和存储模型，不执行 RX 固件；没有连接陀螺仪或防抖执行器。

## 线路与处理阶段

原厂 `103bc296` / `103bc2ba` 通过 GPIO 资源 `ae` 拉低、拉高片选。
模型将 PDR `0428202c` 的位 1 接至从设备片选，遵循高半字写掩码；
SPI 的 RUN 位不代替片选。主控半字 DMA 按低字节优先交换。
片选寄存器仅在接入本设备时映射，保留默认配置的寄存器和迁移布局。

片选拉低时固定本次发送缓冲区，收到的字节存入独立的接收窗口；
拉高时才检查命令和长度。窗口上限 276 字节。截断、溢出或非法长度
计为错误，不能产生数据写入。后续传输才能取得异步生成的读取结果。

`F1` / `F2` 以长度字段减 16 得到数据量，最多 256 字节。
已实现的范围是：

- `F1` 标志 0、键 `aa55`：校验通过后写入 16 KiB 虚拟通信 RAM。
- `F1` 标志 4：校验通过后写入独立的 256 字节配置窗口。
- `F2` 标志 0、键 `aa55`：从虚拟通信 RAM 读取，生成键、地址、
  长度、数据和加法校验对应的回复；只支持完整落在 `[0,0x3000)`
  的范围。更高地址依赖缺失的驻留闪存视图，予以拒绝，不映射到 RAM。
- `D0` 标志 0、`F2` 标志 1：交换先前准备的回复，不提前完成工作。

RAM 初值及复位值为零，不表示从实机取得的校准或驻留数据。
忙状态由待处理的定时任务决定，错误由实际解析或校验失败产生；
没有写入原厂内存来修正回调或长度。功能处理间隔 `work-delay-ns`
默认为 200 微秒，仅是实验参数，不是实机时间测量。

读取结果在后续片选周期中完整送出后才消费；短传输保留待发结果。
未建立的描述符键、驻留操作、固件更新及防抖控制命令均拒绝，
不提供成功确认。普通回复没有传感器载荷，传感器就绪位保持未设置。
因此这个选项不能用来声称防抖、传感器数据或原厂 RX 启动已经实现。

## 观察与验证

QOM 路径 `/machine/master-body-vr` 暴露 `runtime`、`frames`、
`completed`、`rejected`、`truncated`、`reads`、`writes` 和
`configuration-generation`。计数来自实际片选、命令和定时任务。
该可选设备暂不支持迁移。

`tests/test_body_vr.py` 从真实 GPIO 和 SPI FIFO 发包，并通过 HDMAC
通道 4/5 验证低字节优先的 128/256 字节往返。它检查异步忙状态、
校验失败不改 RAM、越界和未知请求拒绝、片选中断、回复消费与复位取消。
这些是合成组件检查，不是原厂拍摄成功证明。

`tools/body_shutter_gate_probe.py --virtual-body-vr` 接入同一设备，
在报告 `body_vr_after` 中记录片选、读写、配置与错误计数。
原始控制器证据见[成员和消费者分析](body_vr_member.md)，原厂带镜头
拍摄的越界位置见[镜头观察](lens.md)。

## 带镜头的保存与回放

[持久卡验证](../../artifacts/lens_body_save/validation.json)使用原厂 C1.70、
虚拟镜头及本通信模型，经原厂曝光/静音设置接口和机身半按、全按、释放
触点完成采集。原厂在 NVMe 卡内生成 `DCIM/100NZ7_2/DSC_0001.JPG`，
随后在同一虚拟机中切入回放并完成 JPEG 解码。

卡文件为 3,407,179 字节，主图 8256×5504，另有 160×120、640×424、
1620×1080 三种缩略图。导出保留卡内原始字节，主图的 12,288 个模拟
场景采样点最大 RGB 误差为零；主图及缩略图的四段编码体与编码 RAM
输出吻合。源卡和先前导出的 JPG 保持不变，独立测试卡及临时编码文件
在校验后清理，导出 JPG 保留在本地且不纳入 Git。

采集期间的主核编码器寄存器空闲不能证明未编码；实际编码工作在从核
执行。本次及先前的带镜头观察均记录了 11 份完整编码输出，与已验证的
保存流程逐一同摘要。卡文件、原厂写入完成及回放是独立的保存证据。

原厂保存/回放运行采用显式开启两个设备的构建；最终镜头选项自动接入
同一通信对端，另以 `tests/test_body_vr.py --via-lens` 的实际 SPI4 DMA
和完整镜头组件检查验证。输入为 128×96 灰度测试场景，原厂 DSP 预处理
明确跳过；这不验证真实光学分辨率、彩色处理或完整防抖。
