# 原生显示输出寄存器与中断

以下地址均为 C 1.70 master 的运行地址，镜像基址为 `0x10020000`。

## 驱动合同

驱动全局 `0xb1801248` 的两个指针实测为 `0xb1801250`、
`0xb180126c`。对象 `+4` 分别为通道偏移 `0`、`0x4000`；
对象 `+0xc` 分别为中断号 `0x70`、`0x6f`，即 112、111。
`0x1046bcce` 根据通道选择注册中断，`0x1046bc6c` 是共用处理器。

| 相对 `0x20140000 + 通道偏移` 的位置 | 原厂行为 |
| --- | --- |
| `+0x200` | `0x1046c3c2` 打包格式和处理字段 |
| `+0x204` | 宽度低 16 位、高度高 14 位 |
| `+0x240/+0x250` | 来自配置结构的两个步长字段 |
| `+0x210/+0x220` | 两组四项缓冲地址 |
| `+0x2440/+0x3440` | 另外两组四项缓冲地址 |
| `+0x1200` | 输出控制，启动写 1 或 `0x11`，停止改低两位为 2 |
| `+0x1210` | 中断掩码 |
| `+0x1214` | 中断状态；处理器读出再原值写回确认 |

`0x1046e1ca` 先把掩码写到状态寄存器，再写到掩码寄存器；
`0x1046bc6c` 读状态并写回同值。这支持写一清除合同。
处理器把状态字及对象传给对象 `+0x10` 的回调，实测为
`0x1046efa9`。后者把位 16/20 映射到通知位 1/2，再按通道将事件
放入低/高半字，经 `0x103606e4` 投递到 `0xb1d01610`。

## 原厂运行观察

[验证记录](../../artifacts/display_output_validation/report.json)由
`tools/display_output_probe.py` 生成：达到拍摄前台后暂停全部核心，
读取配置和缓冲首部 256 字节摘要，恢复运行，两秒后再次采样。
摘要只覆盖首部，不能推断整幅图像完全静止。

- 通道偏移 `0x4000` 的宽高为 1024×682，两步长字段均为 1024。
  `+0x210` 为 `0xcbf33000`，`+0x220` 为 `0xcbfdd800`，
  两地址之差恰为 1024×682；`+0x2440` 为 `0xcb4a7000`。
  这些关系支持分平面输入候选，尚未确认像素格式、活动缓冲索引、
  缩放及混合合同，探针不据此生成 LCD 图像。
- 两次缓冲首部摘要相同。输入格式、几何与四通道的缓冲地址全为零。
  捕获状态为 `(2,0)`，挂起字和操作 3/14 槽均为零。
- 旧模型把整个输出块放在普通 RAM，中断掩码和状态都保留
  `0x11f1f1`。这不能被当成真实的完成事件：初始化的确认写入在
  普通内存中只会保存数值。
- 独立有界实验只脉冲输入事件 0、6，通道仍未配置；十秒窗口内
  未观察到输出中断处理器。一次额外的中断注入尝试在连接阶段超时，
  未执行注入，不能用来判断事件效果。

## 模型验证与事件驱动的原厂证据

`tests/test_display_output.py` 以 ARM 存取指令直接执行模型合同：
初始化确认不制造事件、上升沿锁存、掩码门控前不挂起、通道 0/1
分别路由中断 112/111 且引擎隔离、写一清除保留未确认原因、
掩码清零拉低线路但保留状态、保持高电平不重复、复位清除掩码、
状态与输入电平。以上全部通过。

[验证记录](../../artifacts/display_output_validation/report.json)由
`tools/display_output_probe.py --events 48 52` 生成：新模型下稳态
中断掩码保持 `0x11f1f1` 而状态为零（初始化确认写入不再滞留普通
RAM 值）。首拍快照后脉冲通道 1 位 16/20 对应的输入线 48/52：
状态锁存随即被原厂处理器读出并原值写回确认（下一次快照状态已回
零），`0xb180854c+0x2c` 的输出通知索引从 0 增至 **2**——位 16/20
到通知位 1/2 的映射、经 `0x103606e4` 的投递全部由原厂代码执行。
同一窗口内固件向通道 1 `+0x410..+0x424` 写入新配置字
（`0x200`、`0xc00100`、`0xc0`、`0x80000000`、`0x8000`），
事件交付因果推动了显示驱动状态。缓冲地址与 256 字节摘要仍不变。

## 新增模型与剩余工作

`qemu/nikon-z72-display.c` 覆盖主引擎的 `0x20140000..0x2014efff`，
保留配置字，为上述两路状态提供写一清除、掩码路由、复位和迁移。
`/machine/master-display` 的 `output-event` 输入 0..31 对应通道 0，
32..63 对应偏移 `0x4000` 的通道；上升沿锁存状态，中断号分别为
112、111。保持高电平不重复锁存。其他配置字暂只存储，不代表其
硬件副作用已经实现。

模型不会产生像素、自动宣告传输完成或改写固件会话状态。

## 周期完成源与缓冲轮换

`nikon-z72-boot-config` 新增 `display-complete` 属性：帧节拍同时脉冲
两条恢复出的完成线（输入 48/52），交互台与显示探针以
`--display-complete` 开启。[验证记录](../../artifacts/display_output_complete/report.json)
显示稳态下通知索引持续增长（2→3→5→7），且通道 1 的
`+0x2440/+0x24c0` 缓冲组开始轮换帧池地址
（`0xcb4a7000→0xcbbaf000→0xcb82b000`、
`0xcb5fc000→0xcbd04000→0xcb980000`）——完成事件因果驱动了
原厂显示管线的缓冲管理。快照时状态字保持零（原厂逐次确认），
当时采样的缓冲首部仍为均匀填充；首部摘要不能代表整个界面层。

通知计数的增长速度远低于源频率：处理器把位 16/20 合并为单次通知，
且只有在固件主动开启掩码的窗口内才消费事件；未消费的脉冲被
状态锁存合并。下一步是把活动缓冲索引与轮换序列对应起来，
并等待上游捕获会话提供真实合成内容。

## 2026-10-29：背景与原生界面层分离

[候选缓冲审计](../../artifacts/display_candidate_buffer_audit/report.json)
补读六组地址寄存器，每个有效地址摘要覆盖 4096 字节。
背景 `+0x210/+0x220` 仍分别全为 16/128，但轮换的
`+0x24c0` 缓冲首部已经不是常量。
[布局记录](../../artifacts/display_candidate_layout/report.json)
读取完整候选缓冲后，确认原生曝光模式、白平衡、电池、剩余张数等
图形位于另一层。先前把背景亮度平面称为“最终 LCD 输出”是不准确的。

以下绝对地址均属于通道偏移 `0x4000`：

| 寄存器 | 本次实测 | 预览采用的解释 |
| --- | --- | --- |
| `0x20144204/240` | `0x02aa0400` / 1024 | 背景 1024×682、亮度行步长 |
| `0x20144210/220` | `0xcbf33000/0xcbfdd800` | 背景亮度、另一分量平面；不是同一组的两个地址槽 |
| `0x20146110` | 1 | 本次界面层启用条件 |
| `0x20146200` | `0x00030006` | 低五位为 6 的实测布局 |
| `0x20146400` | `0x02aa0400` | 界面层同样为 1024×682 |
| `0x20146440/4c0` | 随完成事件轮换 | 双像素打包平面、逐像素透明度候选平面 |
| `0x20146500/540` | 2048 / 1024 | 两平面的字节行步长 |

打包平面的黑色背景四字节为 `10 10 80 80`；每四字节的前两字节
分别解出两个相邻像素的亮度，后两字节主要为 128。
直接按偶数、奇数位置抽取会把亮度和色度混在一起，产生竖条纹。
第二平面背景为 0，完整字形主要为 255，半透明黑色控件为 128，
与独立 A8 透明度的解释吻合。色度次序、转换矩阵、缩放、层级及
硬件锁存时机仍未完整恢复，不能把这种观察推广到其他格式。

`Machine.lcd_png()` 现提供该布局的只读灰度预览：暂停正在运行的
虚拟机，读取当前槽 0 的背景与界面缓冲、按各自行步长采样，恢复运行，
以逐像素透明度混合亮度，按实测 16/235 黑白电平输出。
只支持同尺寸、偶数宽度的格式 6 界面；遇到其他布局明确报告不支持。
读取失败也恢复原先正在运行的虚拟机。它不改写图像 RAM，也不代替
显示硬件的活动槽锁存或颜色处理。

[原厂预览验证](../../artifacts/display_native_ui_preview/report.json)
使用同一套原厂 master、slave、控制器及实验输入源运行，无方向性事件
注入。完整打包平面亮度两位置分别有 195/198 个不同值，另两位置范围
为 103..128、128..202；透明度平面有 648768 个零、35573 个 255。
通过实际 `Machine.lcd_png()` 得到 22494 字节 PNG，摘要为
`ca9cb2a9e100b578ab13d110d60df6feff08cd6b6c4f0ed796433f60fbc0968a`，
本地核对可见原生界面而无条纹。公开记录只包含统计与摘要。
四个引擎核心的异常字段均为零，输入源计数到 9，快门门控仍为 1。
交互台的 29 项检查通过，其中新检查覆盖逐行填充、双像素布局、
透明度混合及不支持格式时恢复运行。

界面存在不等于传感器图像已到达：背景视频平面仍为黑色，
RAW 输入到处理输出、快门门控及照片写卡仍待验证。
