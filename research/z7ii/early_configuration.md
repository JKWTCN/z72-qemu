# Z7 II C 1.70 原厂早期配置启动

本阶段依据主从固件分析，在原地址主板上从 EG 偏移 0 连续执行到系统初始化
入口 `0x394`，补齐上一阶段首次外设写入之后的配置访问和临时栈。
偏移均为 EG 成员文件偏移，执行地址为 `0x10020000 + 偏移`。

| 启动结构 | master | slave |
| --- | --- | --- |
| 首次外设写入指令 | `0xBDA4` | `0xBDF0` |
| 临时栈顶 | `0x04008F00` | 相同 |
| `0x2B8` 跳转目标 | `0x914` | `0x960` |
| 配置例程 | `0xD700` | `0xD740` |
| 延时循环 | `0xD800` | `0xD840` |
| 本阶段停止入口 | `0x394` | 相同，后续内容不同 |
| 数据异常向量 | `0x10100010` | `0x10034110` |

`0x2B8` 跳转后的原厂实现为 `BX LR`。配置例程保存 `r4`、`lr` 到临时栈，
对 `0x04281028` 和 `0x0428102C` 执行读改写，最后恢复栈和调用者寄存器。
两次延时分别从 40,000 和 8,000 开始，以 `SUBS`、`BCS` 循环到
`r0 = 0xFFFFFFFF` 后返回；不存在外设就绪轮询。实验让这些循环实际执行，
调试断点只用于读取循环返回前的状态。

| 寄存器 | 本阶段原厂行为 |
| --- | --- |
| `0x04264000` | 写入 `0x21` |
| `0x04264020` | 写入 `0x153B0902` |
| `0x04281028` | 清除位 10、11，其余位保留 |
| `0x0428102C` | 位 16..24 写为 `0x163`，清除位 0、1、4..6，其余位保留 |

主板新增四个独立的 32 位、小端、对齐配置字，以及
`0x04008000..0x04008FFF` 的 4 KiB RAM 窗口。四个配置字支持存储、读改写和
机器复位清零。相邻地址及字节访问不能作为有效配置访问。寄存器零复位值和
RAM 容量是实验选择；固件访问模式不足以确认实际复位值、时钟、供电、引脚语义
或真实内部 SRAM 容量，模型尚不模拟这些硬件效果。

```sh
python tools/early_boot_probe.py --master /path/to/eg1840_mas_01700.bin --slave /path/to/eg1840_sla_01700.bin --qemu .build/build/qemu-system-arm --destination .local/early-boot-run
```

输入首先校验完整固件身份及原厂页表中的配置和临时栈恒等映射。每个角色验证：

- 原厂场景：沿复位路径执行，核对临时栈保存的 `r4/lr`、两次延时参数及返回状态、
  四个最终寄存器值、栈恢复和完整页表不变。
- 预置配置场景：仅在实例中预置 `0xA5A5FC00`、`0xDAFEDC73`，检查原厂读改写
  正确保留未涉及的位；该场景单独记录，不代表原厂复位状态。
- 无效临时栈负对照：到达配置例程的 `PUSH` 前清除实例页表中 `0x040` section，
  必须进入 ABT 模式及各自原厂向量基址加 `0x10` 的入口。

各检查点轨迹保存在本地运行目录，精简结果见
[验证记录](../../artifacts/early_boot_validation/report.json)。
`tests/test_board.py` 使用合成指令检查配置字读写、复位清零、访问异常及主从 RAM。

检查、270 项渲染器 ASan/UBSan 检查通过。原厂复位前段、主从
初始化与通信头、显示判断及缺失尾部/XN 负对照回归均通过。
