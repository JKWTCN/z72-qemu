# 引擎两线串行窗口

分析固件的设备表 `0x1239fa40` 可确认四个引擎窗口从 `0x2c018000`
开始，间隔 `0x1000`，中断依次为 214、215、216、217。
两个引擎拥有各自的窗口及总线，名称分别为 `master-i2c0..3`
和 `slave-i2c0..3`。独立机器也按引擎角色命名。

原厂传输入口 `0x1036d414` 配置方向、FIFO 和地址，
中断处理 `0x1036d56e` 读取原因并处理数据或错误。
此前窗口缺少设备，`0x2c01a000` 上地址 `0x38` 的传输等待超时。
新增设备后，断开目标应答会进入原厂中断例程 `0x1036d748`，
实际中断号为 216。

实验设备的寄存器合同为：

| 偏移 | 行为 |
| --- | --- |
| `0x00` | 控制、读写方向、保持传输和 FIFO 清除 |
| `0x04` | 位 `0x20` 表示可读数据，位 `0x100` 表示持有总线 |
| `0x08` | 七位目标地址及传输提交 |
| `0x0c` | 字节数据 FIFO；软件使用字访问 |
| `0x10` | 完成、FIFO 和错误原因；写一应答 |
| `0x14` | 读为待发送字节数，写为接收批次长度 |
| `0x18`、`0x1c` | 时序配置读回 |
| `0x20` | 反向中断屏蔽字 |
| `0x24`、`0x28` | 写一解除／设置屏蔽 |

原因位 0、1、2 分别用于完成、FIFO 请求和断开目标错误。
FIFO 容量为 16 字节，保持状态下的满批次只发布 FIFO 请求，
后续批次通过最后一次完成结束。异步批次延迟固定为 1000 ns，
不是实际电气时序。外围寄存器空洞读零、写入忽略；字以外访问拒绝。
复位取消计时器、释放总线并清空 FIFO、原因及配置，屏蔽字恢复为 `0x2ff`。
没有默认目标，目标连接使用标准两线总线设备。迁移状态尚未实现。

`tests/test_engine_i2c.py` 在两个独立引擎中执行合成 ARM 指令，
检查四路断开目标、屏蔽、应答和中断路由，使用显式寄存器目标
检查跨 FIFO 写入与读取、保持状态的完成时机、访问宽度及复位。
结果见 `artifacts/engine_i2c_validation/report.json`。

原厂采样路径 `0x103d4752` 通过同一驱动请求六个数据字节。
其两种配置使用目标／寄存器组合 `0x1d/0x01` 和 `0x68/0x1f`；
前者对三组大端有符号数据右移四位，后者直接使用三组半字。
采样成功后才更新分类状态并可能发出 `0x42051201` 通知。
这些访问支持三轴采样结构，尚不能据此确定具体传感器型号。

在四条主端总线显式连接地址 `0x68` 的零初始化寄存器目标后，
有界运行仍未观察到采样成功路径。系统保持模式 0、禁止位 `0x40`，
待更新位图达到 5。空白寄存器目标不代表实际传感器的身份或初始化响应；
仍需验证采样初始化、状态通知、前台切换和菜单显示。
