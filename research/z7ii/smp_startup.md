# 第二核启动与启动任务

目标是在每个独立角色内部执行第二个核的原厂启动，使主核通过原厂就绪等待，
验证启动任务实际执行。master 与 slave 仍是两个独立机器，双核不表示双 EXPEED。
以下地址除标注绝对地址外，均为 C 1.70 EG 文件偏移，运行时加 `0x10020000`。

## 固件结构

复位代码根据 MPIDR 的低位选择路径，每核模式栈相差 `0x4000`。第二核先执行
`WFE/DMB`，等待绝对地址 `0x04008FFC` 的 `0xBABEBABE`。这个标记由主核的原厂
运行时启动写入。第二核确认标记后清零应答，进入 `0xAC`，复制／安装同一份原厂
16 KiB 页表，然后等待 RTOS 配置就绪，完成核内初始化。

| 观察点 | master | slave |
| --- | --- | --- |
| 第二核复位等待 | `0xBFA4` | `0xBFF0` |
| 第二核初始 SVC 栈，绝对地址 | `0xB2B84000` | `0xC18F4000` |
| 主核就绪等待 | `0xFE660` | `0x30034` |
| 就绪计数字，绝对地址 | `0xB18AED90` | `0xC1017D40` |
| 第二核就绪例程 | `0xFE68C` | `0x30060` |
| 原厂独占写指令 | `0x101120` | `0x32B18` |
| 启动任务入口 | `0xE3BC8` | `0x15678` |

第二核用原厂 `LDREX/ADD/STREX` 把就绪计数加一，然后等待主核应答清零。
主核读取软件参数 `TKerPrNum`，要求另外一个核就绪。计数满足后，主核应答，
两个核继续进入调度。这个软件配置不能确定物理芯片的实际核数。

## 模型与执行

主板默认保持单核，支持 `-smp 2`；两个 Cortex-A7 的 affinity 为 0、1。
两核共享同一角色的 RAM、配置设备和 GICv2。GIC CPU 接口使用核内寄存器组，
IRQ/FIQ 及四种通用定时器的 PPI 分别连接各核。CPU 型号、CBAR、GIC 版本及
已有平台完成／清零／计数行为仍属于实验配置。

加载器在复位时把两核初始 PC 都设到原厂 EG 入口；第二核不重复加载镜像。
随后验证只改变调试器运行控制、断点和观察点，不写 PC、寄存器、固件指令、
页表、启动标记或就绪计数。

2026-10-10，两个角色各通过三个原厂场景：

- 单核：原厂期望计数为 1，实际为 0；连续四次完整比较循环保持等待。
- 暂停第二核：第二核先到原厂复位等待，仅运行主核仍保持就绪等待。恢复第二核，
  在原厂 `STREX` 前观察计数 0、写入值 1，单步后独占写返回成功且计数变为 1。
- 并行运行：两核一起继续执行，主核通过等待并实际进入原厂启动任务。

两个成功场景均验证释放标记应答清零、原厂源／复制页表一致，以及启动任务位于
原厂堆区的栈。任务入口的实际 SP 为 master `0xB2C71008` / slave `0xC19B5008`。
到达任务入口证明已发生一次任务调度，不表示完整调度或应用就绪。

另用不含固件的 ARM 合成代码，验证 CPU 0→1、1→0 的定向 SGI 1，IAR 的来源核
信息、EOI，以及两个核各自的安全物理定时器 IRQ 29 和中断栈恢复。
双核 GIC 寄存器通过运行中的 ARM 指令访问，避免调试器访问缺少当前核上下文。
原厂 IRQ 处理程序执行仍未验证。

## 新的外设边界

启动任务继续到低层设备初始化 `0x180`，由 `0x294` 提供基址 `0x2C090000`。
原厂 `0x19C` 的 `STRB R4,[R3,#1]` 触发数据异常，DFAR 为 `0x2C090001`，
DFSR 为 `0x808`；异常 LR 为 `0x100201A4`。两个角色均一致。
本阶段未映射这个设备或跳过该访问。后续[字符接口阶段](console_boot.md)已完成其
原厂初始化。当前复现工具关闭字符接口以保留该负对照，错误状态为 `0x1808`；
本阶段原始未映射访问的记录仍为 `0x808`。
LCD、菜单、输入和双处理器通信尚未实现；完整相机启动仍未验证。

## 复现

```sh
python tests/test_smp.py --qemu .build/build/qemu-system-arm --destination .local/smp-irq-run
python tools/smp_boot_probe.py --master /path/to/eg1840_mas_01700.bin --slave /path/to/eg1840_sla_01700.bin --qemu .build/build/qemu-system-arm --destination .local/smp-boot-run
```

原厂镜像先执行身份和结构校验，输出目录必须不存在。证据见
[第二核启动验证](../../artifacts/smp_boot_validation/report.json)。
原有单核存储、中断及计数检查、22 项 Python、270 项渲染器
ASan/UBSan 检查通过；CI 增加合成双核中断检查，未声称运行远程 CI。
