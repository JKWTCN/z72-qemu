# 主从引擎外设 DMA

可选 `nikon-z72-boot-config.peripheral-dma=on` 为每个引擎接入两组八通道 DMA，
地址分别是 `2c020000`、`2c030000`，窗口长度 `0x90`。
`virtual-lens=on` 也会启用它们；主引擎的 `audio-output=on` 同样启用
两组 DMA。默认配置仍保留原实验窗口。
这些设备暂不支持迁移。

## 原厂寄存器及连线

C1.70 主映像的初始化数据由 `12399f94` 复制到 `b1800000`。
`b1805860` 包含 16 个 36 字节对象，资源号 `12a..139`，地址表从
`b180575c` 开始。前八个中断是 150..157，后八个是 142..149。

| 位置 | 原厂字段 |
| --- | --- |
| 全局 `+00` | DE 位 31、轮转仲裁位 28、暂停位 24 |
| 通道 `+10 + n*10` | CA：EB31、PB30、ST29、请求选择 28:24、BC19:16、TC15:0 |
| 通道 `+14 + n*10` | CB：模式 29:28、字宽 27:26、固定源 25、固定目的 24、重载 23:21、EI20、CI19、状态 18:16 |
| 通道 `+18 / +1c + n*10` | 源地址 / 目的地址 |

`102dc398` 开启全局寄存器，`102dc41e` 构造通道描述符，`102dc4ec` 清除
旧状态并开启通道。`102dc2fa` 的中断处理读取状态、确认后调用原厂回调；
`102dc534` 取消通道。计数是 `(BC+1)*(TC+1)` 个传输单位。

SPI 的 11 项消费对象位于 `b1808e20`，步长 104；字节偏移 20/21 的 TX/RX
选择号分别为 `3+2*端口号`、`4+2*端口号`。主引擎发送初始化
`0x103705fe` 仅接受第一组资源 `12a..131`，其 TX 请求现只接第一组。
接收及从引擎请求暂保留连接到两组的既有行为，尚不能据 TX 的范围
检查推断这些路径。音频资源绑定仅接受第二组 `132..139`，合并输出
请求 3、7 接第二组，见[音频 DMA](display_audio.md#合并输出的-dma-请求)。
SPI 控制寄存器 `+0c` 位 `0x400` 与运行使能共同控制请求，字宽来自 `+10`。
TX 请求反映真实 FIFO 空位，RX 请求反映真实可读数据。

## 传输语义与边界

每个 DMA 连接其所属引擎 CPU 使用的本地地址空间。图像传输单元的远端
重映射视图不能用于外设 DMA，否则相同数字地址可能命中另一引擎的普通
内存，而不是本地 SPI FIFO。曾观测到 TX 状态已完成、镜头没有收到任何
载荷；改用本地总线后，原厂头部与载荷均正常完成。

模型支持 1/2/4 字节、普通或固定源/目的、完成重载，以及已明确接受的
非环绕传输编码。软件请求按名义 48 MHz 计算整次传输的虚拟完成时间；
外部请求每次只提交一个真实总线传输单位，再读取请求状态进行仲裁。
请求先完整送达两组 DMA，再由延后回调消费；一组排空 FIFO 产生的下降沿
不会被另一组稍后收到的旧上升沿覆盖。
这是功能时序，不代表周期精确的总线争用模型。

完成状态 5 通过 CI 产生中断；地址环绕 1、取消 2、源错误 3、目的错误 4
通过 EI 产生中断。状态由真实操作产生，固件确认后中断撤销。
未映射访问、只读目的和不支持的寄存器访问不会转换为成功。
对当前 MMIO 设备的重入会在读取源之前延后；真正写入 DMA 自身并触发取消
时，代次检查保留取消结果，不能在返回后覆写为成功。

`tests/test_hdmac.py` 检查主引擎复制不改变相同地址的从引擎私有 RAM，
确认从引擎连接其 CPU 地址空间，并在独立从引擎机器上实际执行复制。
两侧均检查三种字宽、固定源、中断确认、无请求时保持目的、取消、未映射
源/目的、自取消和复位。只读映射拒绝是模型行为，尚无单独的动态覆盖检查。
共享请求检查先由第一组排空 SPI，再让第二组等待并接收下一份真实数据，
确认第二组不能因残留请求读取空 FIFO。
`tests/test_lens.py` 另外验证 SPI 实际 TX/RX 请求驱动的长页传输。
