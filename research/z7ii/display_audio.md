# Z7 II C 1.70 显示、音频和长曝光固件观察

以下偏移均为解码后 master 文件偏移。依据为原厂指令、字面量、描述符和数据表，不是已完成的实机功能验证。输入身份见 [容器记录](container.md)。

## 显示条件

原厂 `0x600346` 读取状态结构 `+0x19E`，与 2 比较后执行属性和模式限制；`0x539EE2` 读取同一字段并与 2 比较，后续 `0x539F14` 调用前一资格函数。状态 RAM 的字面量为 `0xB202BE70`。

九个 `0x444` 位于 `0x2399844`，其前一字为零。按 `0x14000` 初始化记录换算，前一字的 RAM 地址为 `0xB181F8AC`，九个数据项从 `0xB181F8B0` 起。描述符表 `0x92AA24` 的第 32 项（`0x92AAA4`）为该指针；控件使用运行时表地址 `0x1094AA24` 并读取 `+0x80`。

这些关系支持状态字段、资格函数和控件数据的关联。两处判断目前均要求状态字段为 2（工作名称 `DISP`）；状态 3 的画面含义、掩码各位语义、LCD/EVF/HDMI 的布局及绘制结果均未确认。

## 音频路径

| 原厂位置 | 局部行为或数据 |
|---|---|
| `0x241548` | 音频数据路径，读取状态和资源表字段、组装参数 |
| `0x241596` | 音频配置路径 |
| `0x2415D8` | 状态结构字面量 `0xB21E2630` |
| `0x2415DC` | 资源表字面量 `0x118E492C` |
| `0x240E6A` / `0x240CB4` | 数据和配置路径调用目标 |
| `0x5FDAAE` | 菜单对象获取入口，类型范围检查与 index×44 对象计算 |
| `0xB201BD08`（RAM） | 七项对象类型指针表，单个对象步长 44 字节，见[对象类型表](menu_objects.md) |
| `0x619770` / `0x42E636` | 菜单行与事件路由入口候选，完整调用契约尚未确认 |

音频函数有结构字段访问和参数组装证据，不能只凭入口字节相似就认定接口可直接调用。文件读写、堆分配、消息队列、完成回调、停止播放、拍摄触发、属性查询、双卡路径和静音连拍行为仍需研究。已定位位置在 master，尚未证明完整音频行为不涉及 slave。当前项目没有实现音频修改。

### C1.70 音频寄存器契约

[寄存器证据与映射检查](../../artifacts/audio_register_contract/validation.json)
记录完整固件摘要及八个代码窗口的摘要，不包含固件字节。以下地址为
执行地址，文件偏移需减去 `0x10020000`。

`0x1036e4b6` 将通道 1 转为位移 `0x100`，其他输入返回 0；两个原厂
回调分别传入 0、1。寄存器窗口基址为 `0x2c080000`，两组通道寄存器
起点为 `+0x100`、`+0x200`。`0x1036d7fa` 分别用中断号 167、168
注册回调 `0x1036d7d7`、`0x1036d7b7`。这不表示其他通道编号合法。

| 通道内偏移 | 原厂访问证据 |
| --- | --- |
| `0x04` | `0x1036e4c4` 的合并输出写入目标 |
| `0x08` | 控制字；发送轮询检查位 9，位 1 选择分离输出路径 |
| `0x0c` | 格式配置；`0x1036da06`、`0x1036da82` 更新位字段 |
| `0x10` | 状态字；发送轮询检查位 25，中断处理读取并应答位 16、17 |
| `0x14` | 分频配置；位 24..28、18..20、16..17 分别为 5、3、2 位字段 |
| `0x18` | 端口格式配置，两个格式函数执行读改写 |
| `0x30`、`0x34` | 分离输出路径分别写入偶数、奇数源索引的数据字 |
| `0x5c`、`0x60` | `0x1036e3a4` 起读取的两个输出监视值 |

发送函数 `0x1036e4c4` 在 `0x1036e4fe` 循环读取控制、状态，直到
状态位 25 或控制位 9 为 1 才写入下一数据字。`0x1036db04` 先清除
分频寄存器位 30，再更新三个分频字段，最后置位 30。该序列证明
字段宽度及编程顺序，不能单独证明输入时钟频率或分频计算公式。
`0x1036e542` 的输出 DMA 配置按通道选择请求值 3、7；请求值与
具体 DMA 实例的路由仍需核对。

当前 `nikon-z72-lab` 的实际设备树显示 `0x2c010000..0x2c08ffff`
由优先级 0 的 `z72-release-block-lab` 普通 RAM 覆盖，音频窗口没有
设备覆盖层。因此寄存器可读写不代表已具备队列消费、状态变化或
中断行为；发送轮询也不能靠这种 RAM 映射自行完成。

后续设备实现需以真实队列占用推导输出状态，并核对复位、停止及
中断应答。PCM 打包、物理声道顺序、FIFO 深度和阈值、真实采样率、
输入源、从引擎归属及完整原厂播放流程均未验证；不能用固定就绪位
或直接跳过发送函数替代这些设备行为。

## 长曝光数据

master `0x109ED14` 含延长快门速度菜单英文 UTF-16 字符串，`0x18D6218` 含连续整数表：60、90、120、180、240、300、480、600、720、900 秒。它们支持原厂具有延长快门速度设置和最长 900 秒候选数据；是否在某一拍摄模式中生效及设置限制仍需继续追踪消费者或实机确认。

## 加载与更新边界

原厂包包含五成员和独立 master/slave；本项目按完整输入哈希及成员身份检查，不接受其他版本或修改输入。master `0x14000` 的记录为 `[0x12399F94, 0xB1800000, 0xAEDB8, 0x1002006C]`。

部分代码和资源支持 `0x10020000 + 文件偏移` 的局部映射，新增尾部区域的加载、执行权限和容量限制未确认。候选包或独立 master 是否被升级器接受、文件名与机型规则、长度限制及主从版本协调也未验证。CRC 可重建不代表安装路径已确认。
