# 可选资源计时输入

`--sensor-timing-profile` 为原厂资源 80 声明有限的非零计时参数，默认关闭。
它通过现有组 32 存储输入进入原厂加载器，不写运行中的对象、就绪标志或
函数返回值。原厂代码继续选择模式、读取资源、计算计数并构造计时包。
这是一项功能模型输入，不是恢复的工厂资源或物理传感器标定。

## 使用与声明

交互台和机身拍摄探针均接受该选项：

```sh
python tools/web_console.py <existing-options> --sensor-timing-profile
python tools/body_shutter_gate_probe.py <existing-options> --sensor-timing-profile
```

独立生成器要求同时选择资源头，且保持不覆盖已有目录的行为：

```sh
python tools/create_lab_parameters.py --destination .local/timed-parameters --resource-header --sensor-timing-profile
```

生成的资源仍为 `0x180000` 字节，保留版本和 `ENDM` 尾标记。相对资源
基址的行位置为 `be0c0 + 64*group + 16*subtype`。只声明组 1、7、10 的
四个子类型；其他内容与现有零资源头完全相同，包括空的串行程序长度表。

| 行内偏移 | 输入值 | 已恢复的用途 |
| --- | ---: | --- |
| `+2` | u16 4096 | 周期计算输入及除数 |
| `+6` | u16 586 | 回退基数；特殊模式另有消费者 |
| `+b` | u8 1 | 计时包元数据输入 |
| `+c` | u16 72 | 开销字段量化输入 |

这些数值是显式实验假设。回退基数 586 配合周期 4096，在原厂 `/72`
查询公式下给出 33336 微秒，约为 30 Hz。活动模式可通过原厂辅助函数
选择其他计数；不能把回退基数当成所有模式的固定帧率。开销字段的结果
1000 与周期查询的微秒结果属于不同字段，不能直接混用单位。

参数清单与拍摄报告均记录 `sensor_timing_profile`。未启用时继续使用原有
资源头；该选项不自动启用原厂预处理跳过、虚拟镜头、场景源或拍摄。

## 原厂运算契约

[契约结果](../../artifacts/sensor_timing/timing_contract.json)由
`tools/sensor_timing_contract.py` 执行 C1.70 原厂代码产生：

- `102fef74` 将模式 5、11、14 映射到组 1、7、10。
- `103066be` 读取行 `+2` 并计算周期；`10304e3c` 选择计数和开销字段。
- `10304a5e` 查询 `(period * count) / 72`，保留原厂整数顺序。
- `102ffb14`、`102ffc5a` 构造计时包。后续三个不透明计时记录消费者被
  截为边界；计数、周期和元数据构造本身实际执行。

零资源和非零资源各覆盖三种模式的四个子类型，共 24 个计算情形。下表
给出明确合成请求的结果；对象中的辅助选择、偏置和曝光参数会改变计数。

| 模式 | 非零周期 | 非零计数 | 查询结果（微秒） | 零资源查询 |
| ---: | ---: | ---: | ---: | ---: |
| 5，回退分支 | 4096 | 586 | 33336 | 0 |
| 11，选择值 2、偏置 0 | 4096 | 292 | 16611 | 0 |
| 14 | 4096 | 16 | 910 | 0 |

另一个静音曝光相关请求，原厂有理数字段为 `640/192`，选择值为 7，
产生计数 2324、查询结果 132209 微秒。它验证曝光参数参与计数计算，
不把设置值、帧周期与实际积分时长认定为同一个量。

六个计时包情形比较零/非零资源以及无延长、延长输入 0、7383。周期零
减一编码为 `ffff`，计数零减一编码为 `ffffffff`。非零周期编码为 4095；
以计数 292 为例，输入 7383 得到增量 130 和计数载荷 421。检查还覆盖
三个计数副本、七个周期副本、元数据和源对象保持不变。

```sh
python tools/sensor_timing_contract.py --master <C1.70-master> --out .local/timing-contract.json
```

## 验证范围

[整机对照记录](../../artifacts/sensor_timing/validation.json)保留默认资源与
新输入的独立运行、只读入口观察和来源摘要。观察点各限 8 次，不能由
窗口中的调用次数推断完整调用序列或任意其他模式的行为。

两次静音 F8 机身运行分别记录 52、58 个入口事件，各有 8 次计时返回。
资源内计时区域的只读内容与声明的输入一致。新输入下实际观察到：

| 路径 | 周期 | 计数 | 按查询公式导出的微秒数 |
| --- | ---: | ---: | ---: |
| 模式 11，选择值 2、偏置 0 | 4096 | 292 | 16611 |
| 模式 11，选择值 2、偏置 2 | 4096 | 294 | 16725 |
| 模式 11，选择值 4、偏置 0 | 4096 | 586 | 33336 |
| 模式 5，静音曝光相关请求 | 4096 | 2324 | 132209 |

模式 5 的非零周期也实际进入 `102ffb14` 的参数对象。默认输入中的周期
仍为零；附加偏置可产生计数 2，但查询结果仍为零。窗口内没有观察到
模式 14 的计时返回，不能将片段验证当作该模式的整机验证。

两次均生成一帧主 RAW，结束时机身为 `[2,0]`、驱动为 9，四个 ARM 核
采样的故障寄存器均为零。默认/新输入下 RAW 分别比虚拟光圈到位早
33.311880/34.244292 ms，没有恢复到位门控。本轮没有持久写卡或回放
复验；16 个新临时编码图像已清理，原有照片和卡保持不变。

当前像素 DMA 仍由现有输入配置触发；非零计时字段不会自动建立电子积分
起点、读出门控或镜头到位条件。[空串行程序](sensor_serial.md)的边界保持。
原厂 DSP 预处理也仍需单独实现或明确选择已有跳过分支。
