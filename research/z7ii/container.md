# Z7 II C 1.70 容器与成员记录

研究对象为原始 `Z7_2_0170.bin`。以下事实来自更新包及其解码成员；指令、数据和字符串观察与功能推断分别记录。

## 包与解码体

原始包长度为 48,494,024 字节，SHA256 为 `fc0e94f57500a1f0e287c6b9a036c81a5ffceccb8432a377d645b3fa35a19b6a`。解码体长度为 48,493,992 字节，身份及成员哈希见 [固件身份记录](../firmware_identity.json)。

原始包前 `0x20` 字节不属于编码体。编码体起点的 32 字节为空格明文，其余按位置索引选取等价 XOR 掩码恢复——掩码恢复与解码逻辑属于研究期工具，未随本公开仓库发布。公开仓库的 `analyze/decode_z72.py` 仅保留本地已提取镜像的身份检查（长度、SHA-256、CRC 与窗口哈希），只适用于该严格匹配的固件版本。

解码体 `0x20` 的四个大端字为 `[5, 0xD0, 0, 0]`；条目从 `0x30` 开始，每条 32 字节，整数为大端。成员起点相对于解码体而非原始包。

| 成员 | 解码体偏移 | 字节数 | 尾部 CRC |
|---|---|---:|---|
| `ex1840_013000.bi` | `0xD0` | 524,290 | `EB60` |
| `_tpj01_v140.bin` | `0x800D2` | 57,346 | `A0F2` |
| `eg1840_mas_01700` | `0x8E0D4` | 38,239,098 | `9D06` |
| `vr1840_010100.bi` | `0x2505C4E` | 838,664 | `1394` |
| `eg1840_sla_01700` | `0x25D2856` | 8,834,370 | `B691` |

名称字段可能截断，提取文件使用完整 `.bin` 后缀，报告保留原始容器名。成员内容包含末尾两个 CRC 字节。

## 校验与校正

成员 CRC 使用多项式 `0x1021`、初值零、无末尾异或；对成员除最后两字节外计算，与大端尾值一致。所有五成员通过校验。

最后成员结束于解码体 `0x2E3F598`，其后有 16 字节尾部：`c71e0000000000000000000000000000`。其中前两字节 `C71E` 为容器 CRC，后 14 字节为零填充；本次也核对了容器 CRC。不能将解码体最后两字节当作容器 CRC。

早期把编码体起点 32 字节也进行异或的完整流哈希不再作为基线；成员切片不受该前缀区别影响。当前身份记录明确使用保留空格明文的解码体。

## 成员内容观察

- EX：文件偏移 14089（十进制）有 `Z 7_2 Firmware Ex Copyright Nikon Corp.`，向量值 `SP=0x20000C08`、`Reset=0x080002B5` 支持 Cortex-M 类架构判断；完整职责未逐项确认。
- master/slave：文件 `0x20` 均有 `Ver.01.70.02`，有对应的多核启动及 SMP 内核标识。两镜像职责须由任务配置和实际通信代码判断，不能仅由名称断言。
- VR：头部有 `NikonBVR` 字符串；页式机身防抖存储布局见
  [机身 VR 成员](body_vr_member.md)，不能当作引擎引导区成员。
- TPJ：成员和 CRC 已确认，内部格式、架构及外设职责尚未确认。

## 多版本对照

已核对 C 1.10-01、C 1.61 与 C 1.70：三版均为相同的五类成员，
目录头长 `0xD0`，15 个成员 CRC 与 3 个容器 CRC 均通过。
目录边界、成员身份与版本记录见[对照数据](update_versions.json)。
这些检查不使用 K8，也不代表头部 SHA-1 已验证；摘要与引导材料的
关系见[整包摘要说明](firmware_update.md)。旧版包结构检查不会扩大
当前 C 1.70 启动探针的支持范围。
