# C1.70 三轴原始输入

可选 `nikon-z72-acceleration` 设备为地址 `0x1d` 的原厂路径提供
有限的原始输入，不声明物理传感器型号、重力单位或姿态标定。
默认不创建设备；创建后默认也没有样本。显式连接示例：

```text
-global nikon-z72-boot-config.acceleration-select=on
-device nikon-z72-acceleration,bus=master-i2c2,address=29,sample-present=on,sample-x=0,sample-y=0,sample-z=1024
```

使用网页控制台时，在启动命令中加入 `--acceleration-sample 0 0 1024`
即可挂接设备，并在主引擎把 P0.5 配置为输入时提供高电平，供固件选择地址 `0x1d`。参数依次为 X、Y、Z 的原始计数。省略该选项
时，控制台不会挂接加速度设备。

轴值必须在 `-2048..2047` 内。激活且 `sample-present=on` 时，状态
寄存器 `0x00` 返回 `0x08`，寄存器 `0x01` 返回六字节，依次为
X、Y、Z，每轴左移四位后按高字节优先排列。未激活或没有样本时
状态为零，样本接收请求 NACK。样本保持到下一次外部更新，激活后立即
可用是功能模型的选择，不是物理转换延迟的测量。

### 运行中更新三轴输入

以 `--acceleration-sample X Y Z` 启动网页控制台后，在“加速度原始输入”
中填写 X、Y、Z，再点“应用读数”。“当前样本”显示从设备读回的值；
点“撤回样本”后显示“无”。也可以发送本地请求同时更新三个轴，
例如在 PowerShell 中执行：

```powershell
Invoke-RestMethod http://127.0.0.1:8666/acceleration -Method Post -ContentType application/json -Body '{"axes":[31,-72,1000]}'
```

传入 `{"axes":[]}` 可撤回当前样本，再发送三个整数即可恢复。
每次样本接收 START 锁定当时的六字节。即使主机保持总线、分批读取，
中途更新也只影响下一次样本事务。非法轴值或长度会被拒绝。
设备复位后需由固件重新激活，外部样本保留；重启整个控制台虚拟机
则使用命令行初值。直接使用 QMP 时，控制台设备路径为
`/machine/peripheral/acceleration`，用 `qom-set` 写入 `set-sample`
属性，值同样是三个整数或空数组。

## 原厂依据

主固件 `0x103d57e6` 以目标地址 `0x1d` 写入选择字节 0，并接收
一字节状态；`0x103d51cc` 向控制寄存器 `0x2a` 写入 1，等待状态
位 3，再执行数据处理。`0x103d4752` 的变体 1 分支选择寄存器 1，
读取六字节，交换每个半字的字节顺序并解码有符号 12 位轴值。
另一变体使用地址 `0x68` 和不同格式，本设备不覆盖该分支。

### 提供配置与校准记录

网页控制台和参数存储生成工具均接受 `--acceleration-records CONFIG CALIBRATION`。
两个本地文件按顺序提供完整记录，开头 16 字节均为 ASCII `ACCELE`
加十个零字节。工具按原字节复制，保留类型和单位字段。若还需提供
三轴原始读数，另加 `--acceleration-sample X Y Z`。

| 用途 | 1.70 主固件清单项地址 | 存储组及组内偏移 | 复制长度 |
| --- | --- | --- | --- |
| 配置（资源 21） | `0x118d0a50` | 17，`0xa400` | 256 字节 |
| 校准（资源 57） | `0x118d0be0` | 18，`0x100` | 192 字节 |

配置记录的 `+0x20` 会覆盖实验参数中的采样等待值。两份记录以外的
存储字节保持原样。用有区别的测试数据启动控制台，已在主引擎地址
`0x132ca400`、`0x132e0100` 逐字节读回。默认生成的两个存储组在
这两处均缺少记录标记。原厂函数 `0x103d5344`、`0x103d5366`
分别将两份记录安装到所有者结构的偏移 424、428。

### 联合启动验证

```text
python tools/acceleration_boot_probe.py --qemu <qemu-system-arm> --master <master.bin> --slave <slave.bin> --controller <controller.bin>
```

探针从复位启动三份 1.70 配套固件，通过控制台提供临时测试记录和
三轴输入。在原厂首次读取返回处，两份已安装记录分别位于
`0xb7f54400`、`0xb7f6a0fc`，内容逐字节等于输入。选择引脚接入前，
固件走地址 `0x68` 分支，三个读数均为零。接入后固件选择变体 1，
经原厂总线服务返回 `(-23,47,1024)`，随后完成首次处理与待机写入，
能力字 `0xb1807f08` 为 1。该检查在显示同步之前结束，测试记录
只用于验证数据路径；物理校准精度与界面姿态仍待验证。

两次从复位启动、使用相同测试记录，均收到首次方向事件
`0x42051201`。默认样本 `(-23,47,1024)` 得到方向码 2，运行同一
命令并追加 `--acceleration-sample 1024 0 0` 得到方向码 3。
探针在 `0x103eeb7a` 读取固件准备保存的方向码，再在
`0x103eea94` 核对传给应用回调的值。回调提交完成输入 8 后，
两次在 `0x10350dcc` 读到的聚合字 `0xb1868170` 均为 `0x2`。
这是该回调返回途中的瞬时值。方向码与屏幕旋转角度的对应仍待验证。

### 拍摄文件的方向标签

机身快门探针也接受 `--acceleration-records CONFIG CALIBRATION` 和
`--acceleration-sample X Y Z`。在 M 档彩色测试场景下，使用相同的
测试记录和两份独立卡副本，分别以 `(1024,0,0)` 和 `(-23,47,1024)`
拍摄一次。两张卡均新增 `DCIM/100NZ7_2/DSC_0003.JPG`，原有两张
照片逐字节保留。两份新增文件的主图尺寸均为 8256×5504，
EXIF IFD0 方向标签（`0x0112`）均为 1，完整解码的 RGB 像素散列相同。
此结果适用于本次启用实验性预处理跳过的拍摄路径。应用方向回调
和 JPEG 标签写入之间的调用关系仍待确认。
[两次拍摄的输入和输出校验值](../../artifacts/acceleration_capture/validation.json)

两张成片的 285 个不同字节都在 Nikon MakerNote 的 `0x0091`
（ShotInfo 0803）内。解码后的 OrientationInfo 从偏移 `0x0c`、
`0x2c`、`0x4c` 起各有 16 个小端有符号半字，对应 X、Y、Z。
两张照片的 16 组数值分别全部等于各自的原始输入；两张照片的
RollAngle、PitchAngle、YawAngle 字段均为零。这些固定样本验证了
原始轴值从控制台到成片的数据路径，采样间隔和历史顺序尚待验证。

安装 ExifTool 后，可用以下命令从一张成片读出标准方向值和 16 组原始轴值：

```text
python tools/read_capture_acceleration.py DSC_0003.JPG
```

### 复测原厂读取函数

可以用本地 1.70 主固件复测读取函数：

```text
python tools/acceleration_sample_probe.py --qemu <qemu-system-arm> --master <master.bin>
```

探针运行原厂启动前缀以建立内存映射，选择变体 1，向配置函数
`0x103d48d0` 提供一份测试配置记录。该函数实际提交七笔写入，前五笔
使用零值字段，第六笔从 `0x23` 起写入 15 字节（其中控制字节为
`0x2c`），最后向 `0x2a` 写入 `0x2d` 激活设备。配置记录的
`+0x20` 取 `0x51`，走无需等待的分支。

在固件调用总线服务时，探针读取其事务描述符，
通过定时 I²C 控制器发送选择字节并接收六字节到固件指定的缓冲区。
实测线上字节为 `80 00 7f f0 ff f0`，函数返回 1，输出结构偏移
`+2/+4/+6` 分别为 `-2048/2047/-1`，偏移 `+8` 为零。
探针代接总线获取、事务提交与释放；这项验证覆盖原厂读数请求和解码，
联合启动的数据路径另由上节的探针验证。

`0x103d48d0` 从外部配置记录取字段，向 `0x0e/0x11/0x15/0x17/0x1d`
分别写入 2/1/1/2/4 字节，之后向 `0x23` 写入 15 字节。原厂配置
及校准资源仍是上层前提，设备不会代填这些指针或完成事件。

## 有限配置与事务行为

当前支持的配置是前五个配置寄存器全零，`0x23` 的 15 字节中
索引 7 为 `0x2c`、索引 8 为 2，其余为零。它是明确限定的输入
配置，不等于全部外部配置记录均已实现。控制 `0x2a` 接受
`0/1/0x2c/0x2d`，只以位 0 控制激活。激活时不允许重新配置其他
寄存器；完整控制写入在 STOP 时生效，短写、额外字节、错误值和
新发送 START 不会提交未完成的控制。

选择字节后的 STOP 保留选择，支持独立发送/接收；接收完成或复位
清除事务状态。超过一字节状态或六字节样本的读取返回 `0xff`，
不循环补出样本；I²C 接收接口不能在字节级返回 NACK，此处只是
有限读取范围的断开值。复位关闭激活并保留显式配置的外部轴值。
设备暂不支持迁移。

## 验证边界

`tests/test_acceleration.py` 通过真实引擎 I²C MMIO 和虚拟时钟完成
事务，检查默认无样本、配置、激活/停用、正负边界编码、读取越界、
错误及过长控制写入不激活、系统复位和所有轴的范围拒绝。测试不
写入原厂就绪状态。界面姿态显示仍需独立验证。

## 同地址重复 START

总线保持期间向同一地址重新发起 START，现在保留 I²C 对端连接，
直接向对端发送新的 START 事件。此前控制器先结束旧事务，伪造的
STOP 会把尚未提交的 `0x2a=1` 控制写入提前生效。新的测试先保持
控制写入，再重复 START 选择状态；输入必须仍未激活。这一检查在
修复前失败，修复后通过。

新地址请求还会取消上一批次的定时器和活动标志。若重复接收 START
被对端拒绝，则释放连接，仅报告 NACK；不能让旧定时器继续返回
数据或报告完成。测试在发送截止时间前切换到接收，确认只有 NACK、
无总线占用且无虚假接收完成。地址变化仍走既有结束/重新寻址路径，
本次不将同地址验证扩展为跨地址重复 START 的协议保证。

## 保持总线时发送满 16 字节

1.70 主引擎的中断处理函数（`0x1036d686`）在软件发送计数为零时，
检查完成位才调用描述符中的回调。此前控制器在保持总线并发送满
16 字节后只置 FIFO 空位（`0x02`），固件清除中断后直接返回。
现在对端接收整批数据后，控制器同时置完成位和 FIFO 空位（`0x03`），
HOLD 继续保持连接。

在同一笔定时发送后直接调用原厂处理函数，修复后观察到回调参数为
`0x03`，中断状态已清零，总线占用寄存器仍为 `0x100`。
测试使用预置描述符和回调断点，验证范围截至进入回调。
