# C1.70 三轴原始输入

可选 `nikon-z72-acceleration` 设备为地址 `0x1d` 的原厂路径提供
有限的原始输入，不声明物理传感器型号、重力单位或姿态标定。
默认不创建设备；创建后默认也没有样本。显式连接示例：

```text
-device nikon-z72-acceleration,bus=master-i2c2,address=29,sample-present=on,sample-x=0,sample-y=0,sample-z=1024
```

使用网页控制台时，在启动命令中加入 `--acceleration-sample 0 0 1024`
即可提供相同的固定样本。参数依次为 X、Y、Z 的原始计数。省略该选项
时，控制台不会挂接加速度设备。

轴值必须在 `-2048..2047` 内。激活且 `sample-present=on` 时，状态
寄存器 `0x00` 返回 `0x08`，寄存器 `0x01` 返回六字节，依次为
X、Y、Z，每轴左移四位后按高字节优先排列。未激活或没有样本时
状态为零，样本接收请求 NACK。已声明样本保持稳定，激活后立即
可用是功能模型的选择，不是物理转换延迟的测量。

## 原厂依据

主固件 `0x103d57e6` 以目标地址 `0x1d` 写入选择字节 0，并接收
一字节状态；`0x103d51cc` 向控制寄存器 `0x2a` 写入 1，等待状态
位 3，再执行数据处理。`0x103d4752` 的变体 1 分支选择寄存器 1，
读取六字节，交换每个半字的字节顺序并解码有符号 12 位轴值。
另一变体使用地址 `0x68` 和不同格式，本设备不覆盖该分支。

`0x103d48d0` 从外部配置记录取字段，向 `0x0e/0x11/0x15/0x17/0x1d`
分别写入 2/1/1/2/4 字节，之后向 `0x23` 写入 15 字节。原厂配置
及校准资源仍是上层前提，设备不会代填这些指针或完成事件。

## 有限配置与事务行为

当前支持的配置是前五个配置寄存器全零，`0x23` 的 15 字节中
索引 7 为 `0x2c`、索引 8 为 2，其余为零。它是明确限定的输入
配置，不等于全部外部配置记录均已实现。控制 `0x2a` 接受
`0/1/0x2c/0x2d`，只以位 0 控制激活。激活时不允许重新配置其他
寄存器；完整控制写入在 STOP 时生效，短写、额外字节、错误值和
新发送 START 不会提交未完成的控制。

选择字节后的 STOP 保留选择，支持独立发送/接收；接收完成或复位
清除事务状态。超过一字节状态或六字节样本的读取返回 `0xff`，
不循环补出样本；I²C 接收接口不能在字节级返回 NACK，此处只是
有限读取范围的断开值。复位关闭激活并保留显式配置的外部轴值。
设备暂不支持迁移。

## 验证边界

`tests/test_acceleration.py` 通过真实引擎 I²C MMIO 和虚拟时钟完成
事务，检查默认无样本、配置、激活/停用、正负边界编码、读取越界、
错误及过长控制写入不激活、系统复位和所有轴的范围拒绝。测试不
写入原厂就绪状态。完整固件对外部配置记录的读取、校准处理和
界面姿态显示仍需独立验证。

## 同地址重复 START

总线保持期间向同一地址重新发起 START，现在保留 I²C 对端连接，
直接向对端发送新的 START 事件。此前控制器先结束旧事务，伪造的
STOP 会把尚未提交的 `0x2a=1` 控制写入提前生效。新的测试先保持
控制写入，再重复 START 选择状态；输入必须仍未激活。这一检查在
修复前失败，修复后通过。

新地址请求还会取消上一批次的定时器和活动标志。若重复接收 START
被对端拒绝，则释放连接，仅报告 NACK；不能让旧定时器继续返回
数据或报告完成。测试在发送截止时间前切换到接收，确认只有 NACK、
无总线占用且无虚假接收完成。地址变化仍走既有结束/重新寻址路径，
本次不将同地址验证扩展为跨地址重复 START 的协议保证。

## 保持总线时发送满 16 字节

1.70 主引擎的中断处理函数（`0x1036d686`）在软件发送计数为零时，
检查完成位才调用描述符中的回调。此前控制器在保持总线并发送满
16 字节后只置 FIFO 空位（`0x02`），固件清除中断后直接返回。
现在对端接收整批数据后，控制器同时置完成位和 FIFO 空位（`0x03`），
HOLD 继续保持连接。

在同一笔定时发送后直接调用原厂处理函数，修复后观察到回调参数为
`0x03`，中断状态已清零，总线占用寄存器仍为 `0x100`。
测试使用预置描述符和回调断点，验证范围截至进入回调。
