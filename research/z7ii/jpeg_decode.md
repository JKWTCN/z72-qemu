# 原厂照片回放与 JPEG 解码

## 普通回放键与停止采集

[冷启动基线](../../artifacts/playback_photo_baseline/report.json)使用已有原厂照片卡的独立克隆。
回放键按住约 0.263 个计数器秒后释放，没有定向停止同步事件、捕获 API
调用或宿主任务结果写入。操作 18 完成生产者及 UI 分派的结果均为零，
停止驱动到达 12；旧的 `0x3f` 状态没有出现。长窗口结束时已进入空闲应用，
因此末次空白显示缓冲不能代替回放期间的画面证据。

[较短观测](../../artifacts/playback_photo_details/report.json)直接取得原厂回放入口
`0x1073edf2`，末次应用为索引 2，推进 10.327843 个计数器秒。
卡读命令及内存 DMA 已执行，但 JPEG 单元仍停在 `0x39` 模式、控制字
`0x4008`，显示缓冲为空。照片经停机完整解码、与原卡逐字节比较保持，
文件系统检查通过，见[读卡检查](../../artifacts/playback_photo_baseline/card_check.json)。

探针新增可选 `--playback-click`，以计数器时间释放触点；旧的持续按住模式保留。
回放观测定期保存不完整检查点和有界应用、图像寄存器样本，SD 观测额外保留
至多 1024 条命令，避免只截取启动期间的前 256 条事件。

## 解码配置、头部与 DMA 恢复

编码和解码共用 `0x24072000..0x240725ff`、IRQ 105。
`0x103be5f0` 登记解码描述符，`0x103be756` 启动，主侧中断入口为
`0x103bdfea`。解码的输入、输出方向与编码相反：

| 偏移 | 解码含义 |
| --- | --- |
| `0x440` | JPEG 输入地址 |
| `0x430 / 0x434` | Y 与交错 Cb/Cr 输出面 |
| `0x18 / 0x1c` | 头部报告的高度、宽度 |
| `0x410 / 0x414` | 两路输出行跨度 |
| `0x418 / 0x41c` | 活动宽度、高度 |
| `0x420 / 0x424 / 0x428` | 裁剪配置，本后端要求为零 |

[原厂片段检查](../../artifacts/jpeg_decode_contract/report.json)从合成描述符执行真实配置、
启动和两次中断。首次启动仅启动输出侧控制，再置单元启动位；头部通知后，
原厂将尺寸搬到描述符，填写上述跨度、尺寸寄存器，再提交输入侧 DMA。
头部阶段标志为 `0x2000`，不会直接完成请求；码流和两侧 DMA 完成后，原厂
发布 `0x41051402`，累计标志为 `0x62001`。此检查只注入合成寄存器结果，
不证明实际像素或中断送达，MMIO 存储也不模拟确认副作用。

实验后端先解析真实 JPEG 头部并发布状态 `0x0a000000`、子状态位 4；原厂
恢复输入 DMA 后才解码、写输出并发布 `0x0800c000`、子状态位 31。
头部中断使用 `+0x28` 的子状态掩码，DMA 使用 `+0x484`；这个组合是已观察
配置下的功能模型，尚非物理中断路由和时序的测量。

后端仅接受 8 位、三分量、非渐进 JPEG，尺寸上限 8256×5504。
输入有界于 16 MiB；原厂未给输入容量时仍施加此实验上限。
输出必须落在角色对应、实际可写的本地 RAM 范围，两面连续，跨度与尺寸分别
核对，允许原厂的行/面填充。只写活动像素，保留填充区；完整解码无警告、
源与目标不重叠且所有输出范围有效后才写像素。Y 与交错 Cb/Cr 的解释、
上采样和完成时刻仍为实验选择，不是逐位硬件复现；裁剪、缩放、灰度单分量、
其他色彩格式及总线对端输出尚不支持。

`codec-decoded-count` 只统计实际写完的解码。待处理头部标志及计数随复位清零，
加入版本 59 的迁移状态，最低版本也为 59。没有改写原厂任务事件或完成结果。

## 原厂回放要求的子采样格式

[旧照片解码观测](../../artifacts/playback_photo_decode/report.json)取得四次请求：
1620×1080、8256×5504、640×424、160×120。原厂请求均登记格式 1，
旧照片实际为 4:2:0，头部报告格式 2。独立片段确认这种差异返回 `0x2800`，
不配置几何、不恢复输入 DMA；运行中的逐尺寸回退与此拒绝分支一致，但该轮
没有直接观测服务回调的错误码，不能把片段注入结果当作运行记录。

此前使用库默认的 4:2:0 是明确的诊断选择，通用查看器能打开旧照片并不能证明
原厂可以回放。模式 1 的编码现指定 4:2:2；量化表、标准 Huffman 表及原有
诊断像素来源保留。旧导出图片没有重编码或覆盖。

[设备检查](../../artifacts/jpeg_decode_validation/report.json)覆盖主/从、处理启用/关闭及
既有颜色配置；独立彩色 JPEG 验证 Y 和交错 Cb/Cr，检查头部阶段不写像素、
DMA 恢复、独立跨度与尺寸、填充区保持、截断输入、非法输出、错误几何、
非 RAM 来源、确认和复位。已有编码、测量及像素检查同时通过，并新增
模式 1 输出 SOF 子采样为 4:2:2 的断言。合成检查不能代替原厂拍摄、冷启动
读卡、解码完成或 LCD 像素的整机证据。

## 新格式照片与冷启动读卡像素

[重新拍摄](../../artifacts/body_codec_422/report.json)沿用显式曝光、静音及静照预处理
诊断配置，经真实半按/全按触点执行一次机身拍摄，未调用捕获 API。
全按保持 0.252303 个计数器秒，观察推进 3.786585 个计数器秒；结束时
捕获为 `(2,0)`、驱动为 9、静照队列及状态列表均空，四核与控制器故障字为零。

[停机读卡](../../artifacts/body_codec_422/card_check.json)取得原厂保存的
`DSC_0001.JPG`，5160027 字节，SHA-256 为
`0c1d946e47b8c74bebf27042f14ead6d6f01458da0632ccd7dceacf38ba70906`。
主图 8256×5504，内嵌图 160×120、640×424、1620×1080，均完整解码且
SOF 为 4:2:2。四份编码器 RAM 主体在文件中完整匹配；11310 个测试格中心
误差为零，`PROBE.TXT` 保持。宿主没有重编码或修补卡文件。

随后独立克隆该卡并冷启动，普通短按回放，不使用捕获设置调用、静照预处理
跳过或定向停止事件。原厂重新读取并提交 1620×1080 内嵌图，头部报告格式 1，
原厂填写 1632 字节行跨度后恢复 DMA，实际到达 `0x0800c000` 完成中断。
[完整像素比对](../../artifacts/playback_native_422/pixel_check.json)从中断入口只读采集
两面的全部活动字节摘要，合计 3499200 字节，与卡内预览在宿主直接解码为
YCbCr 后逐面完全一致。参考解码避开 RGB 往返取整；只保留摘要，未保存 RAM
像素到 Git。此项验证覆盖冷读卡和真实解码输出，仍不能单凭它断言 LCD 已显示照片。

[整机末次状态](../../artifacts/playback_native_422/report.json)推进 8.614799 个计数器秒，
主侧解码计数为 1，从侧为 0，应用仍为回放索引 2，状态列表空，四核异常字段为零。
LCD 主亮度面仍均匀为 16，与回放前摘要相同；不能报告照片送显成功。
