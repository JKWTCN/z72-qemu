# 控制器供电接口

分析固件确认，D13 为低时，控制器选择第二条两线总线上的供电接口。
初始化先在 D1 发出高、低请求脉冲，等待 G10 的下降沿，再访问
`0x40005800` 总线控制器上的七位地址 `0x38`。这条路径与内部电池
串行接口分开；对端的具体物理型号尚未确认。

`nikon-z72-controller-supply` 提供可选的实验对端。独立控制器机器使用
`supply-data=/absolute/path/supply.bin`，组合机器使用
`controller-supply-data=/absolute/path/supply.bin`。指定文件才会连接对端及
D1/G10；供电选择输入仍由调用方设置。组合机器要求同时提供控制器固件。
独立控制器还需设置 `supply-input=off`，组合运行则通过现有外部输入接口
把 D13 保持为低。

数据文件必须恰好为 176 字节，即 11 行、每行 16 字节。行号对应读取
寄存器 `0x00..0x0a`，只使用下表指定的有效载荷，其余字节不参与报文。
文件中不包含报文校验和。寄存器 6 不支持。

| 读取寄存器 | 有效载荷字节数 |
| --- | --- |
| `0x00` | 9 |
| `0x01` | 1 |
| `0x02` | 1 |
| `0x03` | 2 |
| `0x04` | 1 |
| `0x05` | 3 |
| `0x07` | 2 |
| `0x08` | 1 |
| `0x09` | 16 |
| `0x0a` | 2 |

每次读取在有效载荷后附加逐字节累加的低八位，不计寄存器地址。
读取超出报文尾部返回 `0xff`。写入寄存器 `0xa0..0xa8` 使用同样校验，
其中 `0xa6` 为两字节载荷，其余为一字节载荷。模型保存校验通过的控制
载荷，拒绝未知命令、错误校验和及多余字节；尚未模拟控制写入对实际
供电或后续状态记录的影响。状态记录需要调用方显式提供，不会自动生成
健康电池、设备身份或校准数据。

G10 初始为高，D1 拉高会重新准备应答，随后 D1 下降使 G10 延迟一微秒
拉低。一微秒仅是实验调度延迟，尚未验证实物时序。对端位于控制器复位
域之外，控制器系统复位不会清除外部对端；整个机器复位会重置协议和
控制载荷，保留输入文件定义的读取记录。

原厂此路径启用控制器总线 DMA。总线模型现在提供接收、发送请求，
按使能位、传输方向和可用数据状态门控。已观察到的连接是 DMA1
流 2 / 通道 7 接收、流 7 / 通道 7 发送。只有数据寄存器新增字节访问，
其他配置窗口仍要求字访问；第一条总线的 DMA 路由尚未连接，末字节
自动应答结束的精确线路时序也尚未建模。

独立原厂控制器已自行通过握手，首个逻辑命令 7 的三字节读取返回成功，
并执行到初始化结束位置 `0x08028898`，控制器异常状态为零。合成检查
验证了全部读取尺寸、校验和、未知命令拒绝、长非法写入边界及双向 DMA
传输和缓冲区保护。

组合运行使用全零实验读取记录时，已进入模式 3，完成 218 次图形上传、
332 条绘制命令，没有图形请求错误。但整理后的供电记录仍为分类
`0xff`、状态 2，应用策略标志仍为 2，五秒限制仍存在。全零记录只用于
确认传输链路，不能作为正常供电配置。完整记录语义、控制写入效果、
稳定启动及菜单交互仍需继续验证。观察数据见
[供电接口验证](../../artifacts/controller_supply_validation/report.json)。
