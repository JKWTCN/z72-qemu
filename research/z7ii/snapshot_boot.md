# 配置快照与批量源读边界

控制器链返回后,库初始化链(master `0x1E003E` / slave `0x32F7E`)调用配置快照
函数:master `0x1E7310` / slave `0x33B18`。以下代码位置均为 C 1.70 EG 文件偏移,
运行时加 `0x10020000`。两角色指令布局相同,仅位置不同。

## 门控与寄存器快照

函数先把 1 写入门控字 `0x20010044`,然后执行 19 次指针解引用复制:指针表位于
早期复制 RAM(master `0xB18A9660` / slave `0xC1013C40`,按复制记录回推到文件
偏移 `0x24235F4` / `0x850114`),每项指向 `0x2001xxxx` 块内的一个寄存器字,
读出其当前值并逐字写入 RAM 目标区(master `0xB2B40C10` / slave `0xC18B164C`)。

两角色的 19 个目标完全一致:`0x20010038/0x2001003C`、`0x20010100..0x2001011C`
(10 个)、`0x20015004` 与 `0x20015020..0x2001503C`(8 个)。这一来源在原厂
执行中被逐指针核对。寄存器初始值按零建模,快照结果因此为 19 个零;真实硬件
上这些字在此时可能已有非零状态,该假设未经证实。

## 批量源表与数据流向

寄存器快照后,函数从 `0x20014800` 起复制 512 个字到快照区之后(迭代数由源
地址算术右移 20 位得出,`0x20014800>>20=0x200`),最后把门控字写回 0,恢复
r4/r5 并尾跳到 master `0x1E70C0` / slave `0x338B0` 的后续初始化。

对固件的引用分析表明:`0x20014800` 在启动流程中没有任何写入者,仅被本函数
与另一处后段代码以池常量引用,并作为数据成分出现在多处数据表中。快照目标区
结束地址 `0xB2B4145C`(master)恰是后续代码使用的 12 字节记录表基址:该处
代码按记录查找地址并做 `目标-记录首字+记录次字` 的换算,支持将其视为地址
映射/翻译记录的判断。记录表位于本次复制内容之后,由何方写入尚待后续阶段
确认。

据此,`0x20014800` 被视为系统控制器块内的只读表,模型按零初始化提供
0x800 字节字访问窗口(读写均落存储,原厂仅按字读取)。零取值与寄存器字的
零复位假设一致;真实硬件内容未证实,若后续消费方行为异常需重新评估。

## 尾跳参数块与下一边界

尾跳函数(master `0x1E70C0` / slave `0x338B0`)从指针表末项(master
`[0xB18A96AC]→0xB18A97F0`,slave `[0xC1013C8C]→0xC1013E18`,均为早期复制
RAM 中的数据块,两角色前 8 个字完全一致)读取参数块,分五段写回
`0x20013000` 起的外设寄存器区。`0x20013000` 块整体尚未接入,首次写入即中止:

| 角色 | 写指令 | DFSR / DFAR |
| --- | --- | --- |
| master | `0x1E70DE` | `0x808` / `0x20013000` |
| slave | `0x338D2` | `0x808` / `0x20013000` |

此前记录的 `0x20014800` 读异常(`DFSR 0x8`,位 11 为写标志,故读访问不带
`0x800`)已由本阶段的零表模型越过。

## 有限模型

`nikon-z72-boot-config` 新增 20 个纯存储字(门控字 `0x20010044` 加上 19 个
被解引用读取的寄存器字)与一个 0x800 字节的零初始化源表区。设备状态格式升
为版本 10。`snapshot-config=off` 时不注册这一块,保留 `0x20010044` 的未映射
写异常(`DFSR 0x808`)作为负对照。门控位的真实作用(快照窗口使能一类判断)、
寄存器字语义与源表真实内容均未实现/未证实。

## 验证与复现

2026-10-10,两个角色各通过原厂和关闭场景。双核从原厂复位连续执行:进入函数
时核对 RAM 指针表与文件推导的 19 指针一致;越过零表批量读后核对门控字写回 0、
19 个快照字与模型值一致、512 个源表字按零复制;随后尾跳参数块在 `0x20013000`
首写处按预期中止。同时重跑控制器链、引脚组与字符接口探针(各自显式关闭本块
以保留记录边界)、`tests/test_board.py` 与 `analyze/` Python 检查,全部通过。

```sh
python tools/snapshot_boot_probe.py --master /path/to/eg1840_mas_01700.bin --slave /path/to/eg1840_sla_01700.bin --qemu .build/build/qemu-system-arm --destination .local/snapshot-run
```

完整证据的精简版本与源码、报告哈希见
[验证报告](../../artifacts/snapshot_boot_validation/report.json)。RTOS 完整调度、
原厂 IRQ 处理与菜单仍未验证。
