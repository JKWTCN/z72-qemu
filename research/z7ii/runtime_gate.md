# 运行时门控与双引擎中断

固件分析定位到启动任务在门控完成事件上的等待。以下文件偏移属于
原厂 C 1.70 master，运行时地址为文件偏移加 `0x10020000`。

| 路径 | 文件偏移 | 行为 |
|---|---|---|
| 初始化 | `0x3665B6` | 创建互斥和事件对象，登记中断 250 的处理函数 |
| 中断使能 | `0x3665F4` | 使能中断 250 |
| 请求 | `0x366602` | 选择门控 bank、清除事件、提交命令并等待事件 |
| 完成处理 | `0x3665A8` | 向 `0x04287004` 写 1，然后设置事件 |
| 状态判断 | `0x3666FC` | 读取 `0x0428700C` 的对应 bank 位 |
| 引用获取／释放 | `0x36665A`／`0x3666A2` | 维护 bank 的引用状态，必要时发起请求 |

请求向 `0x04287008` 写 1，并向 `0x04287010` 写 `0xA1`。
`0x04287000` 的位 12..14 选择 bank，位 8 表示启用或关闭。
模型同步设置或清除对应状态位并保持中断，直到原厂处理函数应答。
状态位在应答后保留，供引用管理路径读取。
`gate-completion=off` 保留请求与原厂等待，供负对照使用。
设备状态版本为 23，保存门控、传输、定序和通信控制寄存器页，
恢复时重新驱动中断线与就绪引脚。

双引擎的 GIC 分核接口必须使用各自 CPU 组的起始编号。
第二组 CPU 的全局编号为 2、3，本地编号为 0、1；配置
`first-cpu-index` 后，第二组的定向中断和私有定时器能够正常投递。
共享消息 RAM 与配置寄存器仍使用各自的地址空间视图。

实验性节拍默认间隔调整为 10 ms。1 ms 间隔在软件执行中可能使较低优先级
的门控中断长期得不到服务。间隔可以通过 `timer-tick-us` 调整；
它不是已确认的硬件定时单位或周期。

内核延时另由 CPU 通用定时器驱动，中断号为 29。初始化在 master
`0xE52EC` 向分发器偏移 `0x300` 写入位 29；GIC v2 的设为活动语义
会把该中断永久留在活动状态。实验配置改用 GIC v1 的只读活动状态接口后，
原厂处理函数 `0xE7AEC` 和重装回调 `0x260` 正常执行，控制器初始化中
`0x44BD4A` 的两次延时调用均返回 `0x44BD4E`。实际硬件版本仍待确认。

双引擎原厂探针默认采用 `-icount shift=0,sleep=off`，按指令数推进虚拟
时间，避免宿主执行速度改变定时顺序。合成中断测试单独运行指定核心，
使用普通虚拟时钟；该测试不验证原厂实时行为。

传输控制块的复位请求在 `0x39D4B2` 向 `0x20100004` 写零。
模型在 `0x20100018` 锁存位 0，并保持中断 102。处理函数 `0x39CE38`
读取三个状态字并写回应答；回调 `0x368C18` 收到位 0 后设置事件位 1，
使等待返回到 `0x368828`。只模拟复位完成，数据传输和其他事件源仍未实现。
`transfer-reset-completion=off` 保留原厂复位等待作为负对照。

## 串行与定序内存传输

正常初始化创建的串行后台任务会通过字节访问配置 `0x2C09000C`、
`0x2C09000D` 和 `0x2C09000F`。前两个地址与既有半字格式寄存器共享
存储；最后一个保存辅助控制字节。该任务的周期延时不是错误退出路径。

定序控制文件有四个通道，每通道九个字，起始地址为 `0x04251010`，
步长 `0x30`。首三个字为字节数减一、源地址和目标地址。控制字在
通道偏移 `+0x18`，提交位为位 28、1、0；状态在 `+0x20`，
低四位 8 表示成功，1 表示当前模型无法完成请求。原厂处理函数分别使用
中断 45..48，读取状态、清除状态和提交位、调用回调并恢复等待任务。

模型通过所属引擎的物理地址空间执行有界内存搬运，只接受递增的 RAM
传输，拒绝设备地址、固定地址模式和超过 16 MiB 的单笔请求。
高位地址按无符号 32 位描述符读取。传输同步完成，真实总线时序待确认。

代码缓存的原厂范围为 `0xBAA00000..0xBB300000`，包含此前只支持的
`0xBAB00000` 载荷暂存页。原厂定序请求把三个窗口分别填充到
`0xBAA00000`、`0xBAC00000` 和 `0xBAF00000`，随后由原厂页表代码
切换执行映射；模型不改写页表，也不向代码缓存预填固件。
辅助固件请求还使用 `0x00000000`、`0x50000000` 和 `0xB1000000`
三个内存族，当前只提供有界存储，辅助处理器执行和握手尚未实现。

首笔原厂请求从 `0x12449E00` 向 `0xB2BB1080` 搬运 289,748 字节。
探针对整个结果与用户提供的固件逐字节比较，并验证原厂中断处理、
状态应答和等待恢复。禁用完成的负对照保持等待。

## 双引擎通信

原厂启动的主处理器就绪输入为 `0x04282018` 位 3，从处理器输出为
`0x04282020` 位 10。双引擎机器将双方输出连接到对方输入，寄存器写入
采用高半字选择、低半字电平的语义。`peer-gpio=off` 提供断开对照。

通信控制块在 `0x20130000`，中断号为 127。主处理器向偏移 `0xC90C`
提交 6，从处理器收到事件 1 后提交 4，双方收到事件 2；主处理器随后
提交通道复位，双方收到事件 4。模型只实现这一启动交换及空闲通道的
停止状态，真实时序与通道载荷传输仍未实现。`transport-link=off` 保留等待。

本地通知的置位与清除地址为偏移 `0x6008`、`0x600C`，远端视图为
`0xE008`、`0xE00C`。原厂接收代码读取第二个状态字；两个状态视图
目前均返回待处理位，独立通知掩码语义尚未确认。通知提交锁存中断状态
位 15，原厂处理函数在偏移 `0xD028` 应答。消息位由接收者单独清除。

主处理器消息头位于 `0xB7CF0000`，从处理器消息头位于 `0xC60F0000`。
运行时主处理器通过 `0x460F0000` 访问远端，从处理器通过
`0x47CF0000` 访问远端，均指向同一份共享存储。主处理器自身的大型
内存池包含 `0xC6000000`，因此不能用远端消息别名覆盖这一范围。
新增内存池范围取自固件初始化记录，配置字 `0x2B100000..0x2B10000C`
及 `0x2B200000..0x2B20002C` 仅保存原厂驱动的配置值。

已移除旧有描述符就绪实验对固定堆字段和回调链接的写入。关闭这些
写入后的原厂运行仍完成主初始化，消息被原厂接收代码消费，四个核心
在有界观察窗口内的异常状态寄存器保持为零。回调表由原厂代码建立。
描述符就绪字仍采用本地提交后的响应假设，完整响应协议尚未确认。
设备状态格式为版本 24。这些局部结果不构成完整启动或菜单显示的证据。

## 验证

```sh
python tools/gate_boot_probe.py --master /path/to/eg1840_mas_01700.bin --slave /path/to/eg1840_sla_01700.bin --qemu .build/build/qemu-system-arm --destination .local/gate-run
python tests/test_dual_interrupts.py --qemu .build/build/qemu-system-arm --destination .local/dual-interrupt-run
python tools/sequencer_boot_probe.py --master /path/to/eg1840_mas_01700.bin --slave /path/to/eg1840_sla_01700.bin --qemu .build/build/qemu-system-arm --destination .local/sequencer-run
python tools/runtime_wait_probe.py --master /path/to/eg1840_mas_01700.bin --slave /path/to/eg1840_sla_01700.bin --qemu .build/build/qemu-system-arm --destination .local/runtime-wait-run
```

原厂正对照验证 bank 0 的启用和关闭、中断处理以及等待任务恢复；
禁用完成反馈的负对照检查处理函数和续行均未出现、状态位保持为零。
两种场景只使用执行断点观察，不修改固件、页表、寄存器或等待对象。

合成中断测试覆盖两组 CPU 的四次双向定向中断、各核私有定时器、
应答后的空闲中断号，以及另一组 CPU 记录保持不变。
合成指令测试不证明原厂所有中断处理流程。

运行时等待探针验证两次原厂延时返回、传输复位状态、原厂处理函数及回调、
状态应答和任务恢复。禁用复位完成的场景仍能完成两次延时，但不能进入
处理函数或等待续行。两种场景均无内存异常，也不改写固件或运行状态。

门控与通信探针说明启动跨过了各自的局部等待。完整相机启动、
显示初始化和菜单绘制仍需后续验证。
