# 控制器总线目标与原厂传输

两条总线的窗口为 `0x40005400`、`0x40005800`，目标总线名称分别为
`controller-i2c0`、`controller-i2c1`。默认不连接设备，保留原厂未连接
地址的应答失败路径。模型只接受配置窗口中的对齐字访问。

显式连接目标后，地址字节按七位地址与方向调用目标。地址应答置
ADDR；先读取状态偏移 `0x14`、再读取 `0x18` 才清除 ADDR 并进入
数据阶段。单独读取方向状态不能提前清除它。发送成功置 TXE 和
BTF，发送失败置应答失败位。接收使用两个字节的有界缓冲，支持
重复 START、ACK/POS 控制的一字节、二字节及三字节尾部。STOP
释放总线，保留已接收但尚未读取的字节；禁用外设会丢弃缓冲。
事件使能与缓冲事件使能分别控制状态事件和 TXE/RXNE；错误事件
独立受错误使能位控制。

可选设备 `nikon-z72-controller-register-bank` 提供 256 字节实验存储。
一次写事务的首字节设置八位指针，其后字节写入并递增；读事务
读取并递增，跨末尾回绕。可通过 `initial-state` 指定 1..256 字节的
私有初始数据，未提供的字节为零。机器复位恢复初始内容；控制器
软件复位仅复位总线前端，保留设备内容。地址须为非零七位地址。

```sh
-device nikon-z72-controller-register-bank,bus=controller-i2c0,address=107,initial-state=/private/experimental-registers.bin
```

该设备只用于观察原厂驱动的数据传输，不代表实际电源器件的寄存器
约束、只读状态、看门狗或电气行为。前端暂不支持 DMA、十位地址、
从设备模式、仲裁、时钟延展或实际线速；数据完成为同步实验行为。
前端迁移版本为 2，寄存器设备迁移版本为 1；迁移往返尚未验证。

`tools/controller_i2c_probe.py` 从原厂复位向量执行。实验输入为 C5
高电平、模拟量通道 1/0 的代码值 3001/1800。在地址 `0x6B` 显式
连接寄存器设备，并将寄存器 `0x0B` 的实验身份值设为 1 后，原厂
身份读取函数在 `0x0802AD8E` 返回，身份字段为 1，传输成功字段
为 1。随后原厂配置函数在 `0x0802B3F4` 返回 1，证明其配置写入
与读回校验通过。未连接目标时，原厂身份传输成功字段保持零，
两种场景均无硬件异常。探针只设置执行断点并读取运行状态，不
修改固件运行内存。结果见[传输证据](../../artifacts/controller_i2c_validation/report.json)。

第三个场景另在地址 `0x0D` 连接实验寄存器设备。原厂代码写入
`08 01`，读取四字节状态，再发送结束命令。实验响应明确设为
`08 00 00 C9`；原厂函数在 `0x0802B822` 返回分类值 2，状态字节
为 `01 00 02`，传输成功字段 `0x2001F650` 为 1，无硬件异常。
这证明四字节接收能够进入原厂的三字节尾部处理，并区分两个
目标的传输成功条件；实验响应尚未对应实际器件状态。

继续分析固件可见，电池管理初始化从片内 `0x08004000` 检查四字节
配置标识 `MAKE`。当前 C 1.30.00 映像在该区域为零，原厂代码因而
设置回退配置，包含 `0x2001F644` 为 1。电源判断还依赖后续状态、
电压与配置条件；配置读回成功尚未使电源任务发布就绪事件。
初始化任务仍等待该事件，串行服务后续初始化和双引擎连接尚未
完成，完整启动与菜单显示均未验证。

合成测试 `tests/test_controller_i2c_targets.py` 覆盖两条总线、指针
回绕、地址应答顺序、重复 START、接收尾部、缓冲中断屏蔽、未连接
地址和机器复位。原有未连接总线与禁用 START 完成测试继续保留。
