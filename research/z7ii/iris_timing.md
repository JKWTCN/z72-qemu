# 光圈坐标与 RAW 生成时序

原厂 FNumber 设置、实际光圈位置和 RAW 生成是三个观察边界。
[坐标契约](../../artifacts/iris_timing/coordinate_contract.json)执行原厂片段，
[原厂运行记录](../../artifacts/iris_timing/validation.json)从设备事件核对同一
虚拟时钟上的目标、运动完成和 RAW 写入。

## 原厂坐标契约

普通镜头族的 `1031086a` 将请求和参考有理数归一到分母 192，计算非负
差值，并受相对最大关闭量约束。`10377dea`（A0）和 `10377e5a`（A3）把
结果的无偏置分子写到载荷小端半字 `+1..2`。

绝对字段采用另一种编码：原厂 `103795cc` 读取状态载荷 `+9..10`，减去
384 后保存为分母 192 的有理数。因而编码 960 对应 `576/192`，即 Av3；
Av6 相对 Av3 的关闭量是 576。不能把绝对编码 960 直接当作相对电机位置。

`tools/lens_aperture_contract.py --master ... --out ...` 检查四个绝对值、
六个相对关闭量和八个目标载荷构造结果，包括等值分数、负差归零及上限。
它使用合成的普通族选择、最大关闭量和包缓冲服务；原厂坐标运算及目标
字段写入实际执行。该检查不包含其他镜头族、传输校验或硬件时序。

## 可选事件

QEMU 的 `-trace enable=...` 可分别启用：

- `z72_lens_iris_request`：完整请求验证成功后记录命令、选择子、当前位置、
  目标、声明的移动时长以及是否真正开始运动；重复目标记录 `started=0`。
- `z72_lens_iris_complete`：电机定时器真正到期后记录坐标和完成代次。
  阶段 ACK 不产生该事件，复位取消的运动也不伪造一次完成。
- `z72_scene_raw`：成功写完预览或主 RAW 后记录帧号、场景通道数、采用的
  光圈、Q16 系数及两个目标地址。主从分片合为一帧，失败请求没有此事件。

三个事件均保留 `QEMU_CLOCK_VIRTUAL` 纳秒时间，默认关闭。它们只记录现有
状态，不新增状态、改变目标或发布驱动完成。RAW 事件表示内存写入完成，
不能解释为已经恢复传感器积分起点。

## 原厂 F8 观察

原厂接口读回 FNumber 800 后，经机身触点拍摄。相对关闭目标实际为 576，
与原厂坐标片段的结果一致。以这次关闭请求为零点：

| 事件 | 虚拟时间差 | 坐标 |
| --- | ---: | ---: |
| 接受 A0:06 关闭请求 | 0 ms | 0 → 576 |
| 主 RAW 写入完成 | 25.895300 ms | 248 |
| 电机定时器到期 | 60.000000 ms | 576 |
| 接受 A0:04 回开请求 | 321.589504 ms | 576 → 0 |
| 回开完成 | 381.589504 ms | 0 |

RAW 比模型到位早 34.104700 ms；其位置 248 与本次线性运动的取整结果
一致，输入快照保留的系数为 26804。结束时机身回到 `[2,0]`、驱动状态 9，
镜头拒绝数为零，四个 ARM 核采样的故障寄存器均为零。

这定位了当前功能模型的顺序：配置触发的 RAW 生成没有等待这次模拟运动
完成。60 ms 是声明的虚拟机械时长，不能从这次顺序推断实物固件故障，
也不能仅把移动时长调短便认定电子曝光已经实现。原厂 DSP 预处理仍明确
跳过；本轮没有持久写卡或回放复验。

后续需要恢复电子曝光、读出起点及镜头到位条件之间的接口。机械输出 16
比较门控不适用于已观察的静音路径；单纯把 FNumber、软件就绪标志或固定
等待写进采集路径，都不能补上该接口证据。
