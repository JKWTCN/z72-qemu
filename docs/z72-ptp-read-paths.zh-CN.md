# PTP 日志读取验证

本轮已确认：配置字节 `0xB20D2D6A` 落在对象 8 的运行时保护范围
`0xB20D2894–0xB20F288F` 内。F032、F033 共用守卫，因此原来的直接开门步骤走不通。

两次实机检查均未写入开关，也未提交转储命令，服务正常退出。
**目前不用再执行相机命令，也不用进入更新菜单。**

## 当前结果如何理解

`completed: true` 只表示本次保护范围检查完成，不代表 RAM 对照成功或 K8 已恢复。

```text
cached_base: 0xb20d2894
cached_bytes: 131068
inclusive_end: 0xb20f288f
configuration_overlaps_cached_object: true
```

区域容量是 131072 字节，与守卫实际使用的 131068 字节缓存长度不同。
配置字节无法直接读写，也不能把当前配置值推断为零。

## 脚本当前可用范围

原 `--execute`、`--execute --read-boot` 实验入口已暂停，
会在连接相机前停止。不要扩大地址、改描述记录或强写配置。

以下只读检查入口保留用于复核，当前无需重复：

```bash
sudo python3 ./ptp_log_read_probe.py --execute --inspect-guard
```

该模式只读取两处固定描述记录，不写 RAM、不改开关、不读引导区。
默认不带 `--execute` 只显示计划，不连接相机。
本地候选材料的 `--verify-material` 离线验证仍可使用。
