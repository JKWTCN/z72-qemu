# PTP 方案 A、B 的前期验证

当前先验证方案 B 是否能读到与 F032 一致的 RAM。
无需进入固件更新菜单，也不要选择更新的最终 Yes。

## 方案 B：固定 RAM 对照

在 WSL 中，从项目根目录进入工具目录：

```bash
cd tools
python3 ./ptp_async_ram_probe.py
```

这条命令只显示计划，不连接相机。
工具固定读取 USB 描述符和文本命令表两处 RAM，各 32 字节。
每处顺序为 F032、F044、F032；没有自定义地址或 RAM 写入选项。
F032 基线内容必须足够丰富，USB 描述符还须匹配相机型号标识；
基线不符合条件时，会在对应的 F044 请求之前停止。

相机正常开机、处于拍摄界面并已连接 WSL 后，执行：

```bash
sudo python3 ./ptp_async_ram_probe.py --execute
```

沿用之前读取工具的 PyUSB 环境。结果自动保存到新的
`../.local/ptp-async-ram-日期时间/`，重复运行不会覆盖旧结果。
目录中包含六份读取数据和 `report.json`；中途失败也保留已取得的结果。

看 `report.json` 中的 `fixed_ram_comparison_passed`：

- `true`：两处 RAM 的 F032 前后稳定、内容不是简单全零等常量，F044 与其完全一致。
- `false`：不能确认 F044 与 master RAM 地址一致；查看出错阶段或各处比较结果。

**即使通过，也只证明这两个 RAM 地址的读取对照通过，不能证明引导区可读。**
本工具不请求引导地址，也不会自动继续尝试其他地址。

F044 对端语义仍待实机验证，可能返回错误或等待超时。
工具使用较长等待时间；如果传输超时或响应错位，会停止后续命令，
不在失去同步的连接上继续发送退出请求。保留输出，先检查相机和 USB 状态。
标准会话及服务模式切换可能影响相机界面，读取不等于界面完全不变。

## 方案 A：已完成的离线核对

从 `tools` 目录执行：

```bash
python3 ./ptp_read_path_probe.py --master ../../../Temporary/2610/07/Z_72/eg1840_mas_01700.bin --output ../.local/ptp-read-paths.json
```

该命令仅分析本地固件，不连接相机。
原始代码执行结果确认：

- 只改变 `0xB1800474` 可以满足命令入队门槛，但不会同时设置日志留存门。
- 原始日志输出选择函数会一起更新 `0xB1800474` 和 `0xB180048C`。
- 日志留存门未开启时，串口冲刷任务会排空记录；开启后记录才会留在环中。
- 恢复串口输出后，之前保留的记录会被排空。

日志记录每项 128 字节，文本从偏移 16 开始，文本长度位于偏移 12 的两字节字段。
离线对照用的是合成 RAM 数据，尚未证明实机会消费 PTP 入队的文本。
因此本阶段没有提供方案 A 的实机写入脚本。
