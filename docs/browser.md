# 浏览器交互台

`tools/web_console.py` 在本机启动组合模拟器，并提供实时画面与按键页面。
仅需 Python 3.12 或更新版本的标准库及已构建的 QEMU，无需安装前端依赖。
三份原厂固件通过本地路径加载，不会传给浏览器或外部服务。

## 启动

Windows 使用 Linux QEMU 构建时，在项目根目录运行以下 PowerShell 命令，
将固件路径替换为本机实际路径：

```powershell
& 'C:\Users\15056\AppData\Local\Programs\Python\Python312\python.exe' tools/web_console.py `
  --qemu .build/build/qemu-system-arm --wsl `
  --master D:\firmware\eg1840_mas_01700.bin `
  --slave D:\firmware\eg1840_sla_01700.bin `
  --controller D:\firmware\ex1840_013000.bin
```

Linux 或原生 Windows QEMU 可使用相应 Python 和 QEMU 路径，省略 `--wsl`。
默认启用实验取景配置：模型产生动态 RAW12 棋盘，
原厂固件配置处理输出、提交显示缓冲并绘制相机界面，页面的 LCD 区域
显示彩色界面与单色测试背景的合成。启动时同时开启对应的帧、处理和完成通知配置。
`--live-view` 保留为显式开启选项；`--no-live-view` 可关闭这组配置以作诊断，
但这种精简配置尚不能稳定完成菜单退出后的采集重启。
它仍使用实验传感器源与有限格式的处理模型，不代表真实传感器颜色、
校准或照片保存；完整拍照仍在开发中。
增加 `--sd-card D:\cards\camera.raw` 可将 raw 卡镜像接入从引擎 SD
主控。会话写入保存在临时覆盖层，关闭模拟器或点击“重启模拟器”后丢弃，输入镜像保持原样。
当前原厂通路按扇区寻址，使用完整的高容量卡镜像（大于 2 GiB；
已验证 4 GiB），不要只截取其中的分区而改变设备容量。4 GiB
拍摄实验已验证目录及目录记录写入，照片文件生成仍待验证。
随后打开 [本机交互台](http://127.0.0.1:8666)。可用 `--port` 更换端口，
或添加 `--open-browser` 自动打开浏览器。页面会在固件启动期间显示进度，
出错时显示原因并允许重启。关闭终端中的服务可使用 Ctrl+C。

增加 `--nvme-card D:\cards\express.raw` 可接入实验性的主引擎 NVMe
存储端点，可与从引擎的 `--sd-card` 同时使用。必须提供完整 raw 设备镜像；
写入保存在临时覆盖层，重启或退出后丢弃。该端点使用原生 PCI/NVMe
队列与块设备后端，控制器读写验证与原厂文件系统验证分开记录，见
[存储端点说明](../research/z7ii/nvme_host.md)。此可选设备暂不支持迁移及保存虚拟机状态。

LCD 区域现按亮度、交错色度和原生界面的逐像素透明度生成彩色预览，
可显示菜单的彩色标签与选中项。背景支持已建模的全高或半高色度布局，
界面支持同尺寸的双像素打包布局；不支持的配置会显示读取错误。
转换与既有像素后端保持一致，尚未应用面板的可编程颜色矩阵或校准表。
`--live-view` 的模拟传感器源仍为单色，不能由界面彩色推断传感器彩色已实现。
修改代码后须重启控制台并刷新页面。验证范围见
[显示预览记录](../research/z7ii/display_output.md#彩色只读预览)。

增加 `--virtual-lens` 可连接实验性的 50 mm F2.8 镜头、外设 DMA 和 SPI4 通信对端。

增加 `--eye-sensor` 可在主引擎 I²C2、地址 `0x38` 连接可选眼距传感器
寄存器模型。默认关闭；支持标识、配置和复位，不提供光学测量值或
测量中断，因此不能用此选项声称自动取景器切换已经实现。

`--sampling-output-complete` 启用实验性的采样输出单比较计时器，默认
关闭。它依据固件配置的比较值、门控和中断掩码交付一次比较事件；
不直接完成拍摄请求。支持范围及时间单位依据见
[采样同步](../research/z7ii/sampling_sync.md#可选的单比较事件模型)。
原厂固件执行镜头探测与配置，M/A/S/P 模式和对应拨轮响应已验证。
该选项默认关闭，暂不支持迁移；镜头参数和电机时序为虚拟输入，
不代表真实光学曝光或完整自动对焦。实现及验证边界见
[虚拟镜头](../research/z7ii/lens.md)。
带镜头的定向实验已验证 NVMe 卡内 JPG 保存及同机回放，见
[保存验证记录](../artifacts/lens_body_save/validation.json)。该实验使用原厂设置接口、
模拟灰度场景及明确的 DSP 预处理跳过；默认浏览器配置下的完整拍照仍待验证。

`--processing-resource-header` 可显式补充内部存储组 23：在 `0x13420000`
提供 `0xe0000` 字节的全零实验区，仅末尾带存储尾标。该输入用于观察
资源 71 的原厂装载通知及静照准入，不是有效校准数据，不保证图像质量。
选项默认关闭，与 `--sensor-timing-profile` 独立；它不跳过处理代码，
也不直接改写运行中的资源位图。对照依据见
[默认快门配置](../research/z7ii/default_shutter_profile.md)。

## 操作

- 交互台默认启用取景链路与按键中断：页面按键可用后轻按 MENU 可
  打开原厂菜单。快速点击会被有界保持到前台完成
  切换为止,等效于一次正常按压。
- 菜单打开后,EXIT(扩展输入 0,页面主键区与 <kbd>X</kbd> 快捷键)退出
  菜单并回到拍摄应用;方向键移动高亮,确认与播放键按原厂行为工作。
- 默认配置已验证 EXIT 返回拍摄画面后再次打开菜单；等待页面恢复按键可用
  后再按 MENU。验证使用原厂应用切换，未改写采集状态，见
  [菜单重开验证](../artifacts/menu_reopen_default/validation.json)。
- 画面刷新节奏跟随模拟时钟:本机模拟速度下,菜单在虚拟时间的几十毫秒
  内逐项绘制,人眼约一两秒内完成,属模拟速度而非交互延迟;实时虚拟钟
  与指令计数加速都会让机器无法完成启动,请使用默认时钟。
- 修改控制台代码或页面后,请重启控制台进程并强制刷新页面(Ctrl+F5),
  避免旧页面与新进程混用。
- 菜单打开后用方向键移动高亮、切换标签页；键盘快捷键为方向键、
  菜单 `M`、播放 `P`、确认 `Enter`。扩展按键提供全部 24 路编号输入，
  已从固件输入表确认名称的编号会直接标注。
- `Esc` 或“释放全部按键”释放输入；页面失焦、隐藏或离开时也发送释放。
  若浏览器直接断开，尚未收到松键请求的持续输入会在最后一次心跳后约五秒内释放。
- 半按快门使用 `F`，全按使用空格，也可按住页面上的对应按钮。全按同时
  保持半按触点；松开全按时，独立保持的半按不会被释放。快门经控制器
  原厂扫描、传输和主引擎解码，已验证机身触点与实际 HTTP 请求的按下、
  交叠和释放状态。传感器实时像素和照片文件生成仍待验证，见
  [机身快门验证](../research/z7ii/body_shutter.md)。
- “拍摄模式”选择器驱动原厂模式拨盘输入；同一个控制台进程重启模拟器时保留
  所选位置。主、副拨盘的 `+` / `−` 按钮各转动一格，具体设置由原厂当前模式
  和菜单决定。每个拨盘最多排队八格；模拟较慢时需等待固件处理。
  `Esc`、释放全部或页面失焦会取消未完成的拨盘输入，模式位置保持不变。
  输入与曝光设置的验证边界见[模式与拨盘](../research/z7ii/exposure_inputs.md)。
  命令行 `--mode-position` 可设置启动拨盘位置：0=P、1=S、2=A、3=M、
  4=U3、5=U2、6=U1、7=AUTO，默认 0。拍摄探针也支持此选项；它设置
  控制器 ADC 输入，曝光属性设置不会代替这个实体拨盘输入。
- “持续刷新画面”只控制画面抓取，不暂停模拟器；“重启模拟器”执行冷启动，
  自动按菜单随重启重新布防。

## 菜单固件更新

页面右下的“菜单固件更新”面板配合以下启动参数使用：
`--update-image` 提供更新文件——整包格式（带 32 字节空格标记，
文件头携带原厂整文件检查所验证的 SHA-1 摘要，需要 `--boot-key`
提供 8 字节引导区密钥材料）或单成员格式（重算过成员 CRC 的
master 成员文件，作为实验室本地输入无需整包摘要；尚未验证相机
是否接受这种单成员文件）；本仓库
不提供制作或重打包工具，请自行合法取得。`--update-store` 指定
持久更新存储目录（默认 `.local/console-update-store`，跨重启
保留）。

- 安装入口要求**菜单应用为前台**：菜单未打开时服务端拒绝安装
  （HTTP 400），页面按钮也保持禁用。这与原厂“进入菜单执行固件
  更新”的操作路径一致。
- 点击“安装并复位”后，整包输入先检查摘要、成员目录、所有成员
  CRC 与容器 CRC，再选择唯一的 master；单成员输入直接检查
  master。随后校验启动结构（长度在主控存储窗口内、成员 CRC 余数
  为零、版本记录、复位分支、初始化表、通信窗口与引导前缀），
  把它与清单原子写入更新存储，然后把镜像编程进运行中机器的启动
  存储并整机复位——机器在同一个模拟器进程内从刷入镜像重新启动。
  清单是提交点，每次进程启动重新校验存储镜像与清单一致；校验
  失败时回退原厂镜像并在状态中显示存储错误。
- 复位完成后机器运行刷入的 master，页面“当前固件”显示已安装
  版本、摘要与安装时间，暂存行显示验证摘要；“恢复原厂固件”
  以同一复位路径编程回原厂镜像。

整包中的其他成员只做完整性检查，不写入启动存储；当前安装对象仅为
master。旧版样本的包结构可用于对比，但当前启动检查仍绑定 C 1.70。
- 原厂更新路径中的存储卡扫描与文件读取在实验室未建模，由上述
  主机侧输入代替；摘要校验、编程与复位重启已按恢复的算法实现。
  固件管理服务的运行时激活仍是未验证边界。详见
  [菜单固件更新研究](../research/z7ii/firmware_update.md)。

画面由当前模拟器显示表面转换为 PNG，按键通过外部输入进入原厂扫描路径。
页面以 30 FPS 为抓取目标，上一帧请求结束后再调度下一帧，慢请求不会堆积；
隐藏页面或关闭持续刷新时停止抓取。截图像素批量写出，减少跨文件系统的小写入。
该目标表示显示表面的抓取频率；固件生成新画面的速度仍受模拟执行速度限制。

页面另提供 LCD 输出卡：直接读取显示输出通道 1 的原厂配置
（几何 1024×682 与两个全尺寸平面，见
[显示输出研究](../research/z7ii/display_output.md)），合成亮度、色度与界面透明度
作为最终 LCD 输出的观察视图。该读取每两秒以上才执行一次，
避免与按键投递争用监视器锁。使用
`--no-live-view` 时，背景可能保持清屏值（Y=0x10）；默认可见交替
变化的单色测试背景及原厂界面，验证记录见
[显示输出研究](../research/z7ii/display_output.md)。
交互台默认按指令数推进虚拟时间，并启用 30 赫实验帧同步源。
固件按其模拟时钟处理输入和刷新画面：
进度刷新，固件逐项绘制界面时图标会在数十秒宿主时间中依次出现，这属于
时钟选择的代价而非画面传输问题。启动命令增加 `--realtime` 可试用实时
虚拟时钟：本机有界观察中，15 秒宿主时间从仅推进约 0.24 秒模拟时间改善
到约 15.5 秒，绘制明显更连贯；但菜单窗口随之只覆盖约一两秒宿主时间，
人工点击基本赶不上，仅配合自动按下或作交互观察。这个比例不表示每秒
生成的新画面数量。该模式更早暴露尚未建模的外设等待。原有诊断探针仍
保留各自的计时参数，两种时钟模式的事件顺序可能不同。
本机联调按 30 FPS 调度连续抓取 150 帧，实际交付约 29.2 帧/秒，
单次接口耗时中位数约 23.8 毫秒；这不包含浏览器绘制耗时。
性能记录见[画面传输验证](../artifacts/frame_transport_validation/report.json)。
方向键输入 5、4、6、7 分别对应原厂解码开关字的上、下、左、右逻辑位，
确认、播放、菜单为输入 3、8、9；该映射经菜单内逐输入扫描验证，见
[菜单内输入扫描](../artifacts/menu_navigation_validation/report.json)。
网页事件使用宿主时钟，固件轮询使用模拟时钟。为避免模拟器运行较慢时漏掉
短点击，服务按硬件计数器保证每个按下及两次点击间的释放电平至少持续
100 毫秒模拟时间；连续点击保留各自边沿，取消操作则立即释放并清空队列。
这是输入采样窗口，不调用固件菜单入口。菜单键额外按住到前台离开拍摄
应用（上限约四分钟宿主时间），因为原厂菜单启动入口在输入保持期间直接
执行；到达上限或页面请求释放时立即恢复松键电平。自动按菜单（可选）复用
同一按下路径：应用管理器就绪且前台为拍摄应用时按一次并交给上述保持
逻辑。发送前与页面按钮一样等待图形表面可用、至少一次绘制完成且没有失败或
不支持的绘图命令，之后同一启动过程内不再重复按下。
状态查询读取应用管理器，不暂停各核。每个服务实例控制一个模拟器，
建议仅打开一个操作页面，避免不同页面同时发送按键。

待安装更新镜像只能经启动参数提供本地路径。

和 DMA 模型，默认关闭。机身探针接受同名选项并在观察报告中记录。

## 静态场景输入

增加 `--live-view --sensor-image /path/to/scene.pgm`，可用本地图像替换
动态棋盘格。支持二进制 PGM（`P5` 灰度）和 PPM（`P6` RGB），每通道
八位、maxval 255；彩色图也使用同一参数，例如 `--sensor-image scene.ppm`。
宽高各为 1..16384，像素载荷不超过 64 MiB，头部不超过 4096 字节。
支持数字之间的头部注释和 CRLF；截断、额外像素字节、不支持的格式及
非法尺寸会使启动失败。

交互台将输入复制到私有运行目录，原文件保持不变。QEMU 在创建实例时
读入一次，板级复位保留已读数据；修改文件后须重启实例才会重新载入。
图像按活动 RAW12 几何拉伸并做最近邻采样；灰度输入每对像素共享一个强度。
全尺寸两分片使用统一的全局图像坐标。未指定此选项时沿用原有棋盘格。
彩色输入选择显式的 RGGB/RAW12 功能格式，经过客体 RAW 内存、预览或
静态处理、缩略图和 JPEG 色度路径，不直接替换 LCD 或照片。该排列和
颜色算法不代表真实传感器、校准或原厂 DSP；RAW14 场景输入仍未实现。
彩色输入不能与 JPEG 棋盘格伪彩选项同时使用，细节见
[彩色场景契约](../research/z7ii/color_scene.md)。

同时使用 `--virtual-lens` 时，PGM/PPM 场景的 RAW 亮度随镜头实际光圈
位置变化；整帧采样同一位置，每收缩一 EV，模型光量减半。全开和未连接
镜头时保留原输入。这里仍是有限光量模型，快门、ISO、景深和噪声尚未
作用于场景，不能解释为实物曝光已经校准。

此选项只提供像素，不修改固件就绪状态或发布拍摄完成，也不跳过 DSP。
机身探针可用 `--sensor-image ... --frame-generate` 配合显式的处理跳过
实验；其写卡结果不代表默认浏览器配置也已具备相同行为。输入图和生成
照片只保留在本地。定向机身拍摄的场景一致性结果见
[独立读卡检查](../artifacts/body_scene_capture/card_check.json)。
